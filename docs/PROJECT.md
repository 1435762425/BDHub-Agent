# BDHub-Agent 项目文档

当前产品规则，整理于 2026-09-23。实现见[技术文档](TECHNICAL.md)，运行状态见[当前交接](handoff/current.md)。

## 1. 目标与范围

面向 BJN 的 1–2 名运营人员，持续完成“商品准备 → 达人发现 → 稳定身份 → 主动触达 → 回复服务 → 合作结果”。用户决定市场、商品范围、商业条件、预算和超出规则的业务事项；系统执行有事实依据、可恢复、可核验的动作，页面重点展示已处理、等待条件、异常和待决定事项。

当前主流程是二发：找到曾推广同 PID 的正销量或达标视频达人，提供有效且佣金更高的商品卡，邀请制作短视频或 LIVE。IT、BR、MY、UK 共用流程，账号、语言、能力、额度与台账按市场隔离。当前实现范围：B 类视频线索、TapLink 清理、会话页人工文本/卡片发送和身份/画像页面操作目前只在 IT 实现，其余市场待按接入标准补齐（差异见 [TECHNICAL §1](TECHNICAL.md#1-架构与环境)）。其他市场按[接入标准](architecture/market-rollout-standard-v1.md)验收；一发、WhatsApp、样品审批、付费投放、赔偿、MCN 签约和素材制作不自动纳入本流程。

| 市场 | 达人可见语言 | Kalodata 区域/币种 | 货盘来源 |
| --- | --- | --- | --- |
| IT | `it-IT` | `IT/EUR` | Campaign＋普通全托周更；不再新建/续跑类目采集 |
| BR | `pt-BR` | `BR/BRL` | Campaign |
| MY | `ms-MY` | `MY/MYR` | Campaign |

中文仅用于运营辅助；正文、商品短名和卡名不能跨市场回退。旧 BDHub 仅作协议和历史事实的只读参考。

## 2. 对象与不变量

- 市场/机构隔离经营与授权；每市场固定通信和货盘账号，不因增加账号翻倍额度。
- 商品方案由 market、PID、来源、Campaign、期限、佣金和资格共同确定；TapLink 必须精确绑定当前方案。
- 同市场以 OECID 识别稳定达人，handle 是带时间的别名；改名不能重置冷却、拒联、历史或未结事项。
- 发送池位置是达人×商品；关系、冷却、拒联、额度和人工接管按达人共享，同一达人一个关系控制。
- 每次外部写入先保存不可变意图，结果未知只沿原账号、原意图核验；进程存活、受理、送达、合作结果分别计数。
- 资格变化只改变当前投影，不删除历史证据。事件、商品事实、条件和事项带发生/观测时间，不用自由摘要替代。

## 3. 商品准备与自动工作流

启用自动运营后按来源到期时间推进 Campaign/全托 → TapLink → Kalodata → OECID → 发送池，阶段记录输入/输出 generation、断点、计数、平台写入和停止原因。关闭总开关不启动新主链；收信和发送各用独立持久控制。流程细节见 [PID 生命周期](architecture/pid-lifecycle-v1.md)。

### 3.1 来源与发布

- Campaign 每 2 天刷新：先核验上次未知加入，再读取可加入列表、加入合格活动，结果明确后采集已加入活动并筛分。
- 全托每周普通查询。UK 首次及每 30 天按平台一级类目完整读取；IT 保留既有覆盖基线，只执行普通周更，原已停止类目断点不自动恢复。
- 全托普通查询受平台结果窗口限制，只用同 PID 新事实更新已有类目覆盖；范围外 PID 留作查询证据，不扩充基线。不能用较窄普通查询替换覆盖 head。
- 完整读取、去重与数量核对后才能原子发布 generation；未完成时继续消费上一完整版本。用户明确接受某次停止采集的部分覆盖时，可发布带永久 `accepted_partial` 标签的快照，绝不称完整覆盖。
- 每类目独立到末页，核对 reported total、返回行数和唯一 PID；类目间重复不重复计商品。跨页重复先补洞/复读，仅在无新增、重复页精确复现且差额不超过 `max(5, reported total/1000)` 时单列稳定重复行。动态总数、窗口截断和未验证差额保持不完整。
- TapLink、Kalodata、OECID 消费同一上游 generation。Kalodata 以范围完成或真实额度耗尽为阶段终点；当前 PID 不发布部分结果，最多两个市场并行。
- 所有市场经同一出口访问 TikTok，货盘、TapLink、OECID 等平台重型读取同一时间只跑一个市场，其余市场排队错峰；遇到平台验证沿用现有自动验证流程，不因验证停跑。

### 3.2 商品资格

全托来源固定为“高机会商品 → 仅全球销售商品”：累计销量 ≥300，有评分时 ≥4.0，无评分允许；未核实的评分 0 不自行解释；总佣金率－公开佣金率 ≥2 个百分点。全托不设库存数量门槛，但明确下架、治理、失效仍拦截。

Campaign 独立核对 ACTIVE、期限、普通商品库存和额外条款，不套用全托无库存例外。评分大于 4 是二发偏好，剩余期限须大于 45 天；后续剩余期限 ≤45 天即移出严格发送池，当前绑定变 inactive，条款变化变 waiting_refresh。同 PID 另有合格方案时可重新选定。筛分不自动删除历史已选池或历史链接。

### 3.3 标准 TapLink

先备链，再查达人。机构收益至少 1、优先 2 个百分点，达人至少比公开佣金高 1 个百分点：`机构收益=min(2, 总佣金－公开佣金－1)`，`达人佣金=总佣金－机构收益`，使用精确数值。

当前卡必须使用 `commission-1-to-2-v1`、市场登记的命名版本和 `🔥 BJN {short_name} {creator_percent}% {tail}`，精确绑定 market/PID/来源/Campaign；本地化短名缺失不得截断标题替代。一个当前商品方案只认一个经平台回读核验的 `currentListId`；完全相同标准卡幂等复用，历史卡只留记录，不参与新发送。

Campaign 卡随 2 天来源刷新核验，全托卡每周核验；新建立即回读。刷新失败期间使用上次成功且仍属于当前 Offer 的绑定。发送前本地复核材料，不逐条远程刷新卡；平台明确拒卡只暂停对应 PID 等待刷新，发送本身未知则按原意图核验。

创建、核验、本地停用、平台删卡分别记录意图。只有平台回读确认整张列表失效才可删卡，并须完整回读确认；内部佣金/期限变化、暂缺货、混合有效卡和未知状态均不构成删除依据。BR/UK 单条 DELETE canary 验收前只本地停用及只读扫描（实现缺口：BR/MY/UK 目前整段未启用 TapLink 清理，连本地停用与只读扫描也没有）。

## 4. 线索、身份与排序

### 4.1 A/B 线索

- A 类：精确 PID 近 14 天最多 20 位正销量达人，过滤销量缺失/非法 handle。Kalodata 按 `revenue DESC` 读取，同时保存数值 GMV、币种、sourceRank 与原始字符串。
- B 类：同达人×PID 不属于 A，最近 30 天精确关联该 PID 的视频累计播放 ≥1,000，不要求出单；多视频只取最高播放一条，并列取较新发布，不累加、不算播放速度。
- B 首次回溯 30 天，每 7 天重读最近 30 天；已确认作者不重复查。越过门槛时仍须在窗口内，过期按发布时间退出资格。（实现缺口：B 类目前只在 IT 运行、随每次 Kalodata 阶段整代重建，没有独立的 7 天节奏；新一代开始时会先清空当前 B 类位置，见 [TECHNICAL §2.4](TECHNICAL.md#24-线索与身份)。）
- 完整覆盖窗口后发布。视频读取不设人为每日请求/单 PID 数上限；真实额度耗尽保存断点。查询刷新不能复用旧窗口结果冒充新数据。
- 查询 PID 前只按商品销量排序，不猜 PID GMV：先续断点，再按首次销量降序；到期刷新按最早成功时间、销量、PID 排序，缺销量按 0。额度耗尽不拿未到期 PID 凑数。

### 4.2 身份

handle 去重查询，精确返回 OECID 为 resolved；平台正常但没有精确 handle 为 unresolved（搜索不到）；验证码、签名、登录、退避、超时或失败为 blocked。前两者复用已判定结果，blocked 从原断点重试，不能写成搜索不到。验证仅在同账号完成并重放原请求，真正成功后才发布身份。

无 OECID 不进入发送池。页面只显示已就位、待补充身份、搜索不到；技术 blocked 归待补充，原因按需展开。

### 4.3 发送位置

A 整体优先于 B：A 按同市场同口径 `GMV DESC → 正销量 DESC → sourceRank ASC → PID ASC`；B 按 `代表视频播放量 DESC → 发布时间 DESC → PID ASC`。同对命中两类合并为 A 并保留视频证据。同达人只领取最优一个位置，其他 PID 等待；佣金决定资格，不作为内部排序键。

同一市场同一达人再次主动推品统一冷却 **72 小时**，已回复或已加橱窗也不缩短；人工客服和针对新来信的回复不因主动推品冷却被禁止。

池只显示可发送、等待中、暂不参与，已发送单列历史。未结回复、人工接管、拒联按达人冻结所有 PID；商品失效只影响相应位置。事项解决后重算资格，不直接放行。

## 5. 持续发送

- 滚动 24 小时新联系本地上限为机构×市场共享 500 人，这是保护门禁，不是平台公布额度；已解锁关系的达人不占新联系名额。无回复前最多 5 条我方消息，卡计一条；卡＋文字要有两个剩余槽位，采用证据/回复按关系规则解锁。
- 每位领取前冻结 creator/OECID、PID、Offer、currentListId、模板 revision、最终正文、关系 revision 与去重键。卡、文字分别保存回执，两者精确回查后才计一次完整触达。
- 平台明确受理并能按原请求回查到 messageId 才是已知成功；平台明确拒绝只结束该达人。unknown 暂停相应意图并只读核验，不能换号或换文重发。
- 16 条固定二发模板按市场翻译、保持语义；参数仅 creator_handle、product_name、creator_commission，后两者必填。至少 10 条当前 revision 审核 approved 才可启动，正文变化退回 pending。同达人已进入意图的话术不重用，耗尽后等待补充。
- 批量模板、人工回复模板、Agent 指南相互独立。历史 frozen 批次只读追溯，不构成当前授权。
- 首次新执行器发送须页面明确启动，此后按持久控制、窗口、额度与断点继续；发布、预检和重启不改变授权。窗口结束、额度等待、单达人限制、平台拒绝和 unknown 分别展示。
- 各市场有合格候选且平台正常时，目标各为 30 位/分钟，以真实卡文确认时间逐市场验收；目标不等于实测能力，不用领取量或进程数代替。

## 6. 收信、Agent 与人工服务

### 6.1 消息与关系

收信独立运行，保存达人入站、橱窗通知及**机构后台实际发出的消息正文**，统一进入会话和 AI 上下文；不得仅凭本系统发送台账重建聊天。消息按市场/账号/会话与精确 messageId 去重，真实平台消息与本地已确认发送只能显示一次；未知或只确认卡片的文字不能当作已发。

新来信冻结该达人全部 PID；上下文按时间、外发 episode、入站 turn、商品与案件组织。收信存活不等于覆盖新鲜，缺失橱窗通知不等于已核实未加入。

合作状态固定 normal/collaborated/paid/rejected；橱窗证据只自动升级系统默认 normal，人工选择优先。paid/rejected 持续排除普通二发；人工明确交还后从最新事件继续。会话队列为需人工、Agent 回复、等待达人、本轮已结束、全部。

### 6.2 当前 Agent 行为

模型按版本化指南生成市场语言的 `reply / no_reply / request_detail / handoff`，确定性代码约束事实、资格和执行。失败逐达人隔离，旧五动作/固定回复仅作历史评测，不是当前执行真值。

达人明确肯定合作、愿意拍摄或直播，但当前商品没有已加橱窗证据时，补充：“可以把上面的卡片添加到橱窗，佣金会在下一个视频或直播中生效～”。须有上文真实卡片，并使用当前市场语言；已加过、已提醒过或纯感谢不机械重复，不能把缺少观测说成核实未加入。

Agent 处理常见样品、物流、售后、佣金结算、合作确认、内容形式、商品卡用法及其他商品咨询：

- 样品申请不到且没有产品可用时自然结束，不追问旧产品；物流售后给平台路径，不承诺代查催发。
- 佣金结算给可能原因和查询路径，不推断真实退款；内容风格由达人决定。
- 其他商品说明二发范围及未来商品网站，不编造样品链接；推广支持只确认会反馈商家，不承诺投放或另建提报待办。
- 无新问题的感谢/表情可不回复；无效方法不重复推荐，多问题逐项回应。

卡打不开/加不了橱窗、我方告知比例与卡不符、固定报价、真实外部联系方式、拒联和针对合作条件/承诺的投诉，先简短确认再转人工。仅请求换渠道先索取一次联系方式；图片/语音不明确先请求一次文字，仍不明再交接。转人工先建案件并冻结达人，确认送达后 AI 停止；等待资料期间不自动催问或超时放行。

### 6.3 运行与页面

Agent 默认北京时间 15:00–16:00，缓冲 30 分钟，主动发送 16:30–24:00；保存设置拒绝重叠。同账号真实写入串行，窗口外等待进程不占 Agent 窗口。

新 Agent 执行器在页面启动首条验证，确认后暂停，用户看回执再继续；现有持久授权不因开发或发布改变。每次回复先冻结唯一正文和意图，未知只核验原意图。页面展示生效指南、provider/model/endpoint、实际输入输出和结果，并提供零平台写入的同合同多轮试聊。

人工“确认处理”只结算当前 case/pending，不发送消息；无需先有人工发送记录。解除接管需核对最新事件，paid/rejected 即使结案仍排除二发。具体合同见[会话与 Agent 设计](architecture/conversation-agent-upgrade-plan-20260923.md)。

## 7. 页面与验收

| 页面 | 任务 |
| --- | --- |
| `/{market}` | 主链、异常、自动运营/全托周更/持续发送控制 |
| `/workspace/send`、`/workspace/history` | 池、模板审核、发送控制与结果 |
| `/conversations`、`/templates`、`/agent` | 三栏会话、模板、指南与试聊 |
| `/catalog` | 全托、Campaign、线索、链接命名四 Tab |
| `/creators` | 稳定身份、别名、画像与线索结果 |
| `/ops/kalodata`、`/jobs`、`/accounts` | 身份、作业时间和账号维护 |

页面复用但市场数据严格隔离，未验收市场动作关闭；不支持全托显示明确空态，接口和 worker 调用为 0。先显示漏斗、覆盖、缺口和下一动作，明细按需展开。Profile 与 PID 线索 GMV 分开，缺值显示未知；统计可追到同范围台账，不把技术读取失败显示为 0。

完成需同时证明：完整 generation 与可恢复断点、稳定身份与材料、72 小时冷却及关系门禁、卡文双回执、unknown 原意图恢复、双向消息覆盖、人工接管和统计恒等式。代码测试、本机服务、平台回执和合作结果分开验收。

下一步优先修复证据/恢复缺口并验证四市场闭环，再评估一发与新渠道；具体建议见[项目审计与清理](implementation/project-audit-20260924.md)。动态进度只更新当前交接。
