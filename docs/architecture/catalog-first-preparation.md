> 历史设计记录：本文关于“满足最低条件的旧链接继续用于二发”的口径已被当前标准链接规则取代。新发送只使用 `commission-1-to-2-v1` + `link-naming-v1` 的唯一 `currentListId`；详见 [项目文档](../PROJECT.md) 与 [PID 生命周期](pid-lifecycle-v1.md)。

2026-09-14。依据产品经理关于全托/非全托货盘、二发事前准备和发送的最新拆分要求。本页描述需要实现的目标与现有差异，不表示链路已经全部上线。

## 已确认的流程

| 阶段 | 全托商品 | 非全托商品 / Campaign |
| --- | --- | --- |
| 发现与刷新 | 高机会商品中仅全球销售商品 | 发现活动、加入活动、刷新已加入活动及商品 |
| 商品初筛 | 累计销量≥300；评分≥4.0，暂无评分允许；总佣金－公开佣金≥2个百分点；无库存数量门槛 | 使用本来源规则，后续单独确认；不把全托300件门槛直接套用 |
| 平台货盘 | 符合初筛的商品加入已选池，并回查 | 确认已加入活动与可推广商品 |
| 链接准备 | 从已选池取得实际活动绑定、分佣，复用有效链接或创建缺失链接 | 在Campaign页面完成分佣与链接准备 |
| 二发可搜索商品 | 已有有效TapLink且符合当前二发商业条件的全托PID | 已有有效链接且符合当前二发商业条件的Campaign PID |
| 达人准备 | 从可搜索PID查Kalodata，保留正销量PID—达人线索；去重、OEC身份和关系核验 | 同左，保留商品来源与实际方案 |
| 发送 | 指定数量、足量准备、固定模板、发送窗口、逐项回查 | 同左 |

发送前对商品方案和链接进行定向复核，不能因为预先建过链接就跳过失效检查。已建链接不等于必须立即搜索达人，搜索批量仍根据用户指定的达人目标和剩余供应缺口安排。

## 货盘与二发任务分别管理

- 货盘准备负责商品、活动、选入和链接，是多个二发任务共用的基础资料，不等待某个任务攒够2100位达人。
- 二发任务从已准备好的货盘链接选择PID，管理来源查询、PID—达人线索、稳定身份、拒联/咨询/联系限制、正式与候补名单。
- 商品卡、短名称和模板变量按商品/方案复用，不为每个达人重复建链或生成名称。
- 商品入池、链接创建、已有链接失效、从货盘移除分别记录，不联动删除有效历史链接。
- 同PID可能对应多个活动，查询线索按PID去重；可用方案与实际卡片绑定保留，不能将不同活动的佣金和期限拼在一起。
- 本轮不恢复消息发送或自动回复。自动回复仍须按意大利案例由产品经理审核后再上线。

## 页面必须解释的数量

全托页主要展示：本轮发现数量、初筛通过数量、筛除原因、当前已选核验数量、有效链接覆盖PID数、待建链PID数、待核验数。商品明细作为下钻，不作为主要操作页面。

“已创建链接条数”和“有可用链接的商品数”分开；分母始终注明本轮/当前筛选。未检查与确定缺链分开。采集时已选标记与当前平台回查结果分开，不能只把历史未选数字继续显示为当前待处理量。

二发事前准备显示每步的输入、输出、规则和失败原因。发送区显示实际完整确认数量和速度曲线。话术模板作为独立设置，不混在诊断结果里。

## 已确认的分佣与复用规则

后续逐项确认：全托与非全托Campaign的新建链接统一分配。机构至少1、最多2个百分点；达人至少比公开佣金高1个百分点，满足后机构优先留2。用总佣金T、公开佣金O表示，差值G=T−O须≥2，机构A=min(2,G−1)，达人C=T−A。使用精确百分比和平台精度校验。

已有平台有效旧链接继续保留，不因与新建分配规则不同而自动另建。旧链接用于二发仍须机构收益≥1个百分点、达人佣金>当前公开佣金，并符合商品当前资格；不达标保留历史但停止新二发。同PID优先选满足这些条件且达人佣金最高的旧链接，同佣金优先已有发送记录；其他旧链接保留。

商品评分跌破4分或总佣金差低于2时，暂停新线索搜索和后续二发，条件恢复并重新核验合格后恢复资格。资格恢复不解除用户对发送或自动回复的全局暂停。

## 已确认的来源与日常运行

- 已有合格链接的PID中优先查询未查过Kalodata的商品，按累计销量降序；支持人工指定范围，人工指定不绕过资格。已查PID的达人线索每7天刷新，保留历史记录、更新当前线索并按稳定身份去重。
- Campaign自动发现并加入可直接加入的新活动，再筛选商品、补齐链接；额外合作条款或资料需求转人工。
- 货盘发现与刷新默认每天北京时间03:00，保留立即执行入口。账号冲突与实际启动时机见[账号调度设计](account-scheduling.md)，尚未启用新的定时作业。
