# 会话与 Agent 回复升级计划

日期：2026-09-23。状态：用户已确认实施；真实发送仍由页面单独启动。

AI 业务规则与会话页面方案来自本次用户逐项确认。开发先同步 `docs/PROJECT.md`，技术变化同步 `docs/TECHNICAL.md`；动态进度更新当前交接页。

## 1. 目标与完成定义

- AI 根据连续对话、业务指南和真实商品上下文自然组织回复，替代“分类后原样发送三条固定模板”。
- 大部分普通沟通自主完成；需要人工核查或决定的事项进入人工队列，并暂停该达人的全部二发。
- 运营可以看到模型接入、实际提示词、实际上下文、结构化判断、最终正文与执行结果，也可以多轮试聊。
- 不设置未经实测的自动处理率目标。报告真实样本上的应自动处理、应转人工、误转人工、漏转人工与回复质量。
- 完成分层：代码与测试通过、影子试答通过、页面可用、各市场 transport 验收、用户显式启动后的实际结果分别验收；前一层不代替后一层。

## 2. 已核实的当前实现

- `apps/web/src/features/conversations/ConversationWorkspace.tsx` 集中实现会话、人工模板和 Agent 设置。
- 当前队列为 `human/agent/completed/all`；`agent` 同时包含待处理和已经处理的记录。`waitingSeconds` 按最近入站/橱窗事件计算，不能代表真实待办时长。
- 当前会话页面没有持续更新机制；列表接口提供分页信息，但组件没有实现继续加载。详情刷新会重新加载草稿、清空临时翻译，需要改造后才能安全持续刷新。
- 右栏同时放事项、合作状态、画像和关联商品；“确认人工回复”与合作状态修改是分离操作。
- `reply_events.py::DeepSeekClassifier` 使用写在代码中的场景分类提示词；`draft_provider.py` 当前固定 `deepseek-flash` 与官方 endpoint。固定模板不是判断提示词。
- `classification_input` 当前取少量相邻入站和关联 episode；相邻消息按时间距离选取，历史重放时需要防止读到未来消息；缺少完整的相关外发文字和已回复内容会影响连续对话理解。
- `run-agent-replies.py` 当前按 IT plan 工作，复用旧五动作与固定模板；多市场页面存在不等于多市场生成及发送均已接通。
- 发送继续复用 `service_reply`、持久请求标识、账号门禁和回查，不另建发送执行器。
- 本次只读查询的 `var/second-cycle.sqlite` 回复事件表有 38 条 IT 入站。不能把该表的覆盖描述成所有市场全部历史会话；旧 35 条分类评测不能直接作为新指南的验收分数。

## 3. 用户已确认的回复政策

### 3.1 总原则与语言

1. 只处理当前实际诉求；达人单纯告知情况时，不主动展开整套样品或合作话术。
2. 参考答案约束含义，不要求逐字发送；结合前文、已尝试方式、对方情绪和已知事实组织简短回复。
3. 不重复询问已知信息，不重复推荐达人明确尝试无效的同一方法。
4. 无新问题的感谢、表情、礼貌结束通常无需再回复；首次问候可自然回应，明显垃圾消息不回复。
5. 不虚构已执行的查询、联系、投放、审核或结果；原因未知时用可能性表达。
6. 按会话所属市场输出：IT=`it-IT`，BR=`pt-BR`，MY=`ms-MY`，UK=`en-GB`。入站语言不同不自动改变回复语言。缺少市场语言配置时不回退 IT。
7. 中文理解供运营查看，不作为达人收到的正文。

### 3.2 场景路由

| 场景 | 处理 | 人工 |
| --- | --- | --- |
| 想要样品、未查看申请方式 | 引导查看对应商品样品申请入口；有入口则自行申请 | 否 |
| 找不到入口或无法申请 | 解释无法另行寄样，自然结束本次合作，可说明后续更合适的二发机会 | 否 |
| 旧产品是否还在 | 不为样品失败专门增加这一追问分支 | 否 |
| 样品审核、发货、物流不动、未收到 | 按实际阶段给查询/反馈建议；已尝试则承接结果；不代查、不承诺催发 | 否 |
| 损坏、错货、售后、补寄 | 建议通过样品申请联系商家处理或更换；不主动追加“我们不能补寄” | 否 |
| 物流/售后反复追问或不满 | 按同类规则继续沟通，不单因语气或次数升级人工 | 否 |
| 明确愿意合作、计划视频或直播 | 简单确认；不追问发布日期，不索取视频链接，不主动催促 | 否 |
| 已加橱窗、已制作、已发布 | 分清进展，感谢或确认；不假装已看过视频，不推断成效 | 否 |
| 内容形式询问 | 没有额外形式要求，达人按自己的风格决定；自然鼓励 | 否 |
| 如何使用商品卡 | 先查看佣金升级，再加橱窗，在下一条视频/直播挂对应商品 | 否 |
| 不知道哪个商品 | 根据上下文指出；多商品确实不明确才简短确认 | 否 |
| 卡打不开、卡不能用、无法加橱窗 | 回复会查看，活动可能失效；不直接认定原因 | 是 |
| 原链接佣金更高或没有升级 | 建议沿用佣金更高的原链接；比较未知时用条件句 | 否 |
| 本次卡比例与我方明确告知不一致 | 回复会核查哪里出问题 | 是 |
| 佣金未到账、到账少、结算延迟 | 提示可能未确认、退货退款、调整或延迟；看明细、稍后查看，必要时平台反馈；不保证日期 | 否 |
| 其他商品、目录、品类 | 解释主要做已推广商品的二发佣金机会；说明未来商品网站上线后分享，不承诺其中都有样品 | 否 |
| 固定费用、报价、特殊付款条件 | 确认收到条件；不议价、不自动接受或拒绝 | 是 |
| 换渠道但未提供联系方式 | 索取一次相应联系方式；等待补充 | 尚否 |
| 提供号码、邮箱或可识别联系链接 | 确认收到，带合作诉求交接；明显不完整则请补全 | 是 |
| 广告/Boost 支持 | “收到，我们会把你的推广需求反馈给商家”；不承诺结果或后续答复，不改为“已提报”，不新增提报待办 | 普通询问否 |
| 没时间、本次不感兴趣 | 礼貌结束，不追问时间，不当作永久拒联 | 否 |
| 明确不再联系 | 简短确认，立即暂停全部二发，交人工确认“不再联系” | 是 |
| 针对我方合作条件、历史沟通、重复触达的投诉 | 确认反馈，核对原沟通 | 是 |
| 图片/语音/含糊消息 | 能理解就按场景处理；不能理解请文字补充一次，仍不能理解才人工 | 条件式 |
| 多个问题 | 逐项回应；纯自动组合仍自动；包含人工事项则交人工 | 按组成 |

“补充一次”按当前未明诉求计算，不是达人终身只能问一次。达人尚未补充时等待，不自动反复追问。物流、售后、结算不能因出现泛化“投诉”标签就错误转人工；混合消息中独立的付费/拒联/卡异常仍按自身规则处理。

### 3.3 参考答案来源与事实边界

- 将本会话用户确认的中文参考答案整理为版本化场景文档，再配四市场自然语言示例。不能只保留场景名称而丢掉用户删除的追问与限制话术。
- 商品名称、佣金、卡、账号、市场、发送时间引用真实关联事件，不让模型凭空选择 PID 或外发账号。
- 普通物流/售后/结算不引入后台查询工具，也不添加给运营的代查任务。
- 当用户只说“没升级”时允许条件式解释；明确“你说 15%，卡却是 10%”必须人工。
- 未来网站和机会只按已确认的未来口径表达，不编日期、链接、具体商品，也不创建自动通知任务。
- 单条参考答案含“没有产品在手”等前提时，仅在上下文支持时使用；不能为了套答案去猜事实。

## 4. 人工接管合同（已确认）

- 按市场内稳定达人身份控制全部 PID。任何人工案件未完成，普通二发均暂停。
- 判定需要人工时立即落接管和暂停，不等待确认消息成功后才暂停。
- 为首次交接确认冻结唯一回复意图；只允许这一条交接确认在人工模式下执行，不能因此开放所有 AI 回复。人工开始操作、控制 revision 变化或明确要求取消时，旧待发确认必须失效。
- 确认消息失败/unknown 不撤销人工暂停、不另建重复确认；只回查原意图。人工能看到确认是否实际送达。
- 接管后暂停后续 AI 自动回复；新消息归入同一未结事项，保留未读提示和最新事件。
- 完成人工事项时原子提交处理结果与当前消息水位：普通合作可恢复资格、继续处理保持暂停、不再联系持续排除、付费合作排除普通二发。
- 普通合作解除暂停后仍检查商品资格、冷却、未处理新消息与其他正常二发条件，不立即强发。
- 已有付费/拒联状态不被普通“完成”按钮、橱窗事件或新消息清除；恢复需要明确修改对应状态。
- 人工浏览/已读不等于完成，发送一条人工消息也不自动等于整个事项完成。
- 人工队列必须有明确的手动解除按钮。普通完成后解除达人级人工锁，恢复正常二发资格判断；不能靠“发送过消息”或超时自动解锁。

## 5. 技术设计

### 5.1 从分类器升级为回复决策器

新增可独立测试的上下文构建、提示词编译、回复生成和决策校验模块；继续通过固定 argv CLI 与 server bridge 暴露，不让 React 直接操作数据库。

建议决策结构：

```json
{
  "schemaVersion": "reply-decision-v2",
  "route": "reply | no_reply | request_detail | handoff",
  "intentCodes": ["sample_unavailable"],
  "evidenceMessageIds": ["actual-message-id"],
  "replyText": "market-language text or null",
  "meaningZh": "当前达人诉求的简短中文理解",
  "reasonCode": "sample_unavailable",
  "reasonSummaryZh": "基于可见证据的简短处理理由",
  "waitFor": "none | contact | clarification",
  "handoffReason": null
}
```

输出不含可直接执行的 SQL、账号、发送参数、永久标签或任意工具调用。`reasonSummaryZh` 是简短、可审核的判断说明，不要求展示模型隐藏推理过程。互斥关系由代码校验：no_reply 无正文；handoff 有合法原因；request_detail 有等待类型；普通 reply 不携带人工或任意业务写指令。

生成时模型一并判断全部诉求和组织正文。不要把场景树重新实现成固定正文选择器，也不要宣称几条关键词检查就能完全保证语义合规。结构和状态用确定性代码保证；语义质量通过指南、真实案例和评测约束。

### 5.2 上下文与时间边界

输入包括市场/locale、当前用户确认指南 revision、处理到的消息水位、按时间排列的相关双向消息、原二发邀请与卡信息、已确认的 AI/人工回复、当前人工/付费/拒联状态、联系方式/澄清已经问过的记录。

- 历史重放严格截止在目标消息时刻，不能读取之后的消息、处理结论或人工真值作为输入。
- 不将只生成但未发送的草稿当成达人看过的回复；未确认发送单列并阻止冲突动作。
- 当前未处理的连续入站作为同一决策输入；在冻结发送前验证没有更新的消息水位。出现新消息则废弃旧候选、按最新上下文重新判断。
- 不仅取“最新一条入站+两个相邻入站”。优先保留当前未结对话及关联外发；长历史按可配置输入预算裁剪，记录裁剪范围，保留原始消息证据。
- 摘要只作辅助，不能替代原消息、达人状态或商品事实。缺少历史如实记录，不补造曾经做过什么。
- 同市场同达人跨 PID 共用会话责任；跨市场上下文严格隔离。

### 5.3 提示词与模型接入

提示词由稳定输出合同、已确认业务指南、市场语言规则、当前会话数据编译。聊天正文作为数据，不成为修改系统规则的指令。

沿用现有 DeepSeek provider 作为首个实现；展示其实际服务商、模型、endpoint 和凭据配置状态。首期不默认增加任意 provider 切换、任意 URL 或密钥管理 UI。若需要编辑连接，单独确定范围。

设置页显示：可编辑业务指南、当前生效版本、草稿版本及差异、可展开的完整编译提示词。用户保存生效版本采用 revision 校验；回退是发布新的版本引用，不改写历史调用记录。

每次生产生成和试聊记录真实输入/输出及版本。试聊使用与生产相同的编译器和生成器，但执行端永远不调用平台 transport、不改生产 case/pending/control。

### 5.4 数据与持久化

沿用 `inbound_turn/outbound_episode/service_case/inbox_pending/relationship/service_reply` 和合作状态表，不另建平行会话或发送台账。

以下是新增逻辑数据，实施前核对现有迁移，优先扩展可复用表；迁移号取当时下一版本，不在计划中硬编码：

| 逻辑对象 | 最小字段与约束 |
| --- | --- |
| 指南 revision | scope、revision、正文、场景示例、语言配置引用、创建/生效时间、内容 hash；append-only |
| 决策/调用记录 | market、plan、creator、mode、消息水位、context hash、指南/连接 revision、实际 messages、provider/model、结构化结果、usage、错误、耗时 |
| 已处理诉求状态 | 当前等待类型、澄清所属诉求与次数、已处理水位；依附既有 pending/case，不复制人工责任状态 |
| 发送关联 | decision ID → 唯一 service_reply ID；正文、locale 和证据版本冻结 |
| 人工完成事件 | request ID、case/control/pending revision、处理水位、结果、操作者及时间；幂等 |
| 试聊记录 | session、市场、合成/历史来源、消息轮次、决策与评分；与真实队列隔离 |

凭据不进入输入展示、日志、Git 或模型上下文。业务会话输入保存在既有本机私有状态范围，公开文档和测试使用脱敏或合成样本。

### 5.5 执行器、并发与恢复

- 扩展 `run-agent-replies.py` 为显式 market/plan 路由，禁止运行时硬编码 IT 或读 IT 模板补缺。
- 复用 `AutoReplies` 扩展受控生成正文准备路径，保留旧发送与回执，旧 kind 不重写。历史 ready 候选、旧人工分类与新政策不能直接混用。
- 旧五动作 `turn_review` 标注政策版本；新评测另存新合同，不能让旧 human/no_reply 真值覆盖新业务分工。
- 决策缓存键包括市场、达人、输入水位/hash、指南 revision、模型配置与控制 revision；不能只按 turn ID 查旧分类。
- 同一达人以已有 lease/fence/写门禁串行处理；不同账号/市场不串用锁、身份或进度。
- 保留现有时间窗口、缓冲和与二发的互斥合同，暂不把回复改为即时发送；时间策略变化另行讨论。
- API/模型临时错误显示运行异常，不伪装为“达人需要人工”；重试是有界、可见的模型调用恢复，不能变成未知外发重发。
- `inflight/accepted/unknown` 只核验原发送意图，不换号、换正文或新建发送绕过未知结果。
- no_reply 和等待状态仅在确定没有更新待处理消息时推进相应水位；拒联/付费/人工暂停不能被自动结案解除。
- 不新增广告提报、未来网站通知、物流催办或样品处理作业。

### 5.6 附件能力

“能理解则处理”是产品目标，不代表当前纯文本 provider 已支持图片和语音。首期必须如实标明能力：已具备可用文本/受支持识别结果则使用；没有识别能力则请求一次文字补充。图像识别、语音转写如要接入，列为独立能力和成本验收，不能假装读懂附件。

## 6. API 与模块实施清单

路径名称为规划，保持现有 Route → bridge → 固定 argv CLI → lib 结构。

| 工作项 | 入口/模块 | 实施内容 |
| --- | --- | --- |
| 指南与连接只读状态 | 新 `/api/agent-replies`、对应 bridge/CLI/lib | GET 指南版本、实际连接元数据、语言与运行状态；POST 保存/发布指南，强制 revision |
| 试聊和历史重放 | 同一受控 API 的 simulate/replay 命令 | 持久试聊会话、读取处理记录；请求只产生模型/本机试验记录，不进入真实队列 |
| 决策生成 | 新 context/prompt/decision 模块，复用 `draft_provider.py` | 全部场景、四市场、结构校验、证据与决策存储 |
| 正式执行 | `run-agent-replies.py`、`cycle_auto_reply.py`、既有 transport | 冻结动态正文、交接确认例外、恢复合同与多市场隔离 |
| 会话投影 | `conversation_workbench.py`、conversations bridge | 互斥队列、增量刷新、处理证据、准确等待时长、分页 |
| 人工处理 | `/api/conversations` 扩展命令 | 接管、合并新消息、原子完成结果；使用 requestId 和 expected revisions |
| 二发资格 | `lead_pool.py` 与正式领取/dispatch 门禁 | 人工 case、paid/rejected、未处理新消息一致拦截，UI 和执行一致 |
| 页面 | `features/conversations/` 拆分组件 | 会话工作台、人工模板、指南、试聊、调用记录；保留市场路由 |

GET 只读连接，不通过会创建表的初始化路径检查状态；新写命令保持固定动作白名单和字段白名单。实现长耗时试聊时复用现有持久作业机制，避免只靠前端连接保持执行。

## 7. 会话页面方案（用户已确认）

### 7.1 队列

建议按当前下一步分为四个互斥视图，另有“全部”：

- 待人工：当前有未完成的人工事项，包含人工正在等待外部结果的事项；不能因对方尚未答复就丢失人工责任。
- AI 待处理：等待判断、生成或发送；区分等窗口、开关关闭、运行异常、未知发送等原因，不显示成已在回复。
- 待达人补充：AI 已请求联系方式或必要说明，尚未获得；普通结束语和合作确认不自动进入这一队列。
- 待达人补充期间保持本轮入站冻结和二发暂停，直到补充后的新判断完成；不自动催问或超时解除。
- 本轮已结束：当前无未结动作；不是合作已达成或物流问题已解决。新消息重新评估。

打开页面默认待人工；若为空，显示清楚的其他队列数量与入口，不伪造空白或强行切换。付费/不再联系作为独立合作控制标签及筛选，不混入进度分类。

每行展示达人、最近消息中文理解、处理原因、最后时间、是否有新消息。未读与待处理独立：已读不结案；只有真正未处理的事项显示等待时长，已结束显示结束时间。人工队列建议未读新消息优先，同组按未处理时间排序。

### 7.2 三栏布局与详情

- 保留左队列、中聊天、右事项的结构。聊天占主要宽度，右栏可收起，窄屏改详情抽屉，避免全页和多个窄栏同时滚动。
- 聊天头部显示当前处理方、状态、人工原因及“二发暂停/排除原因”。允许从自动会话主动接管。
- 中间同时保留原文与可切换中文译文；系统事件、二发、AI 和人工消息样式明确，发送状态改为易懂中文。
- 商品卡显示名称、当次佣金、发送时间和卡状态，历史发送比例不能冒充当前实时核验结果。
- 新消息增量进入，不覆盖正在编辑的草稿、不跳走正在阅读的内容；提供新消息提示。
- 右栏首屏优先转人工原因、达人诉求、AI 已回复内容、联系方式/商品证据和当前控制状态；画像指标收起次要展示。
- 点击 AI 消息可查看该次实际输入、提示词版本、判断说明与回执；生成草稿和真实送达必须区分。

### 7.3 人工回复与完成

- 中文编辑 → 市场语言预览 → 用户发送，保留直接写市场语言的方式；翻译不自动发送。
- 自动保存草稿，区分达人和市场；人工模板可搜索、编辑、归档及插入，不被自动加入 Agent 指南。
- “发送最近商品卡”改为可识别的关联卡选择与预览，避免多商品会话发错；可用范围按当前市场 transport 能力展示。
- “确认人工回复”改为“手动解除人工接管 / 完成处理”，在同一操作中选择普通合作/付费合作/不再联系；仍在处理可保留事项，不要求虚构发过消息或填写无用说明。
- 完成页直接显示结果对二发的影响。消息发送 unknown 时保持可见，不以“完成”按钮抹平未确认状态。
- 手动接管的具体交互先确认控制状态再允许外发，不能只在前端改一个标记。跨窗口 revision 冲突保留草稿并提示刷新。

### 7.4 展示选择

原文始终可见，中文译文作为标注清楚的辅助阅读。人工模板保留轻量快捷话术用途，提供搜索、编辑与归档；不并入 Agent 自动知识库。

## 8. 实施顺序与交付

1. **规格定稿**：完成第 7.4 节讨论，更新 PROJECT/TECHNICAL 对应章节，冻结首版指南和各场景参考答案；列清新旧规则变化。
2. **上下文与影子生成**：建立指南版本、调用记录、四市场生成与试聊；首批处理只产生试验记录。交付可见的实际提示词和多轮试聊页面。
3. **人工与二发状态合同**：完成原子接管/结案、交接确认唯一意图、全 PID 暂停、paid/rejected 和恢复检查；以模拟 transport 验证。
4. **会话与模板页面**：落互斥队列、增量聊天、翻译、草稿、事项与 AI 记录；按照用户确认的页面方案实现。
5. **接入既有执行器**：四市场显式路由、动态正文冻结与回执恢复；连接真实 transport 仍保持关闭。市场能力未验收则显示实际不可用，不跨市场替代。
6. **回归、迁移与发布准备**：先核对进程/锁/断点，备份后 additive migration；完成必要测试和只读服务检查。是否重启依赖实际运行核对，不自动恢复 worker。
7. **用户启动后的独立验收**：Agent 页面第一次明确启动只处理首条真实回复；确认回执后停住。用户检查会话证据后可在同页继续自动回复。小范围核验真实回复、转人工与二发拦截，记录业务结果。讨论、计划和部署不是解锁授权。

- Python 按范围运行 unittest，Web 相关 Node 测试、typecheck、build；不为纯文案或低影响视觉变化另写复述实现的测试。
- 模型语义评测使用目标时刻之前的真实上下文与合成多轮案例，保存指南/模型版本和实际输出；合成样本与真实样本分开统计。
- 现有 38 条 IT turn 按新指南重新标注；重复表达不当成独立覆盖。缺少真实多轮/其他市场样本时如实报告，使用合成测试补合同，不宣称四市场实测完成。

| 类别 | 必须覆盖的正反例 |
| --- | --- |
| 连续对话 | 首次问样品→没有入口→自然结束；已用完不再问是否在手；单纯告知不展开售后；试过的方法不重复 |
| 分流 | 付费/商品卡异常/拒联转人工；物流/售后/结算不误转；“没升级”与明确比例不符区分；混合意图不漏答 |
| 联系方式 | 未给→索取→等待→已给才人工；首条已给不再问；明显不完整补全；不可理解补充一次 |
| 市场 | 四市场固定 locale；英语入站 IT 仍意大利语；中文不可成为外发；配置缺失不能回退 IT |
| 上下文 | 历史重放不读未来；多 PID 不串卡；未送达草稿不当已回复；状态与原事件优先于摘要 |
| 人工并发 | 转人工即冻结全部 PID；确认失败不解除；人工操作使旧 AI 候选失效；结案同时有新消息不得丢失 |
| 恢复资格 | 普通完成不清除付费/拒联；冷却与商品资格仍生效；多次完成请求幂等；未完成 case 不被时钟解除 |
| 外发 | 同一输入不双发；重启恢复 frozen 正文；unknown 只查原意图；保存指南不改历史正文；开关关闭不外发 |
| 试聊隔离 | 模型可调用但平台写入为 0，生产 pending/case/control 不变化；GET 不建表、不生成、不发送 |
| UI | 分类计数与列表一致；空态/错误态不混淆；分页可读全；等待时长语义正确；刷新不覆盖草稿 |

验收不以完全匹配参考句子衡量。核对事实、语气、覆盖诉求、是否重复、目标语言、路由与执行结果；必要人工的漏转不能靠整体自动处理率掩盖。
