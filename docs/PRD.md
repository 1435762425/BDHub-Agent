# BDHub-Agent PRD：指定数量的二发批次系统

版本：2026-09-13 批次需求确认版。依据：产品经理逐轮确认。本文及[批次架构](architecture/batch-outreach-v2.md)是当前设计基线，覆盖早期小批滚动补料、自动估算“发满”及同时营销/自动回复的设计。历史研究保存在[归档](archive/PRD-research-before-batches-20260913.md)。**需求确认、代码完成和真实验收分别报告。**

## 1. 目标与边界

V1：全托管主力货盘持续增加可发PID；用户给定明确数量，系统一次性准备足量达人及素材，分批发送、跨日续发，发送结束后按策略转回复。1–2人运营。意大利、墨西哥、巴西先TikTok IM，WhatsApp后续；一发主动推品在V2，工作台保留独立入口。旧BDHub只读参考、按能力迁移；新系统独立运行。

必须填写正整数目标，例如3000或5000。没有“自动估算每日发满”模式，不把每天500新达人的额度当成任务目标上限。只计算任务内去重达人，单人一张PID商品卡＋固定话术全部回查成功计1。失败、未发送、单卡成功和结果未知另列，不计完整完成量。

当前AI自动回复被用户手动暂停。新设计有阶段切换能力，但实现或计划完成不得自动撤销这次暂停；需用户明确恢复。

## 2. 用户操作

1. 自然语言输入需求，或填写表单。
2. 系统生成任务卡：机构、市场、目标数量、商品范围、准备方式（立即准备或附发送计划）、开始日期与北京时间发送时段、约10%候补、模板及商业规则版本、回复阶段设置。
“立即准备”允许发送日期与时段暂缺，马上推进备料；发送窗口判定保持关闭，后续再设置，不编造日期或全天发送窗口。

3. 用户确认一次任务卡。其内正常选品、采集、身份核验、缩名、选入/建链、发送与续发自动推进，不逐人审核草稿。解析有歧义时澄清，不从模糊指令直接执行。
4. 准备不足时显示数量缺口和具体阻塞原因；到计划时间仍未备齐默认等待。用户可显式选择“先发送已就绪部分”，原总目标保持，不自动缩小。
5. 任务详情可暂停、调整排队优先级；已提交动作先核验。修改目标、范围或规则形成新版本，重算未提交部分，历史发送证据不可改写。

## 3. 完整业务流程

指定任务 → 批次选PID → Kalodata批次采集PID—达人 → 去重与身份/关系校验 → 按实际用到的商品批量缩名 → 选入与TapLink准备/核验 → 正式名单及候补备齐 → 等待发送窗口 → 分批发送与逐项回查 → 完成/时段截止/无可发送线索/平台限制 → 核验在途 → 回复阶段或保持人工暂停 → 下一窗口续发剩余任务。

“全量准备”指一次任务的全部目标名单及候补，不是穷举整个市场，也不是平台一次请求发送3000人。平台请求仍按经过验证的接口能力、限速和有界并发执行。发送阶段不再临时进行基本选人、缩名或建链。

### 准备门槛

- 默认正式数量N，候补ceil(N×10%)，候补不增加目标。正式和候补同样必须有完整材料。
- 按市场＋OEC去重；每位达人本任务只选一个有同PID历史带货依据的商品。2026-09-14用户确认：本统计期销量为0的线索直接过滤，不再分析播放量；保留正销量条件并继续扩充合格PID。
- 任务的商品范围包含全部合格货盘、指定PID或限定类目/活动。线索不足不得自行扩大范围。
- 已知稳定OEC保留身份；新handle走精确Find，不因昵称相似或Kalodata ID相同猜测绑定。明确IT身份可先完成身份路径，完整画像缺失不必阻塞二发。
- 关系拒联、人工接管、待咨询、营销频次、当前可联系条件分别校验；“准备好”不提前消耗发送额度。
- 商品名按PID、标题版本和语言缓存；没有逐达人话术模型调用。
- 备用仅替换明确不能发送/失效的成员；未知投递先核验，不能直接换人填数。候补耗尽进入补料/关注状态，不能默默计作目标完成。

## 4. 货盘模块（V1上线前提）

### 主力全托来源

唯一指定的自动发现入口：**高机会商品 → 仅全球销售商品**。不并行采用另一个“全球销售商品”入口。必须补齐分页/覆盖、PID去重、适用市场、当前佣金、期限和平台可用性事实、变化记录及持续入池，并形成真实验收。旧小样或已选池读取成功不代表该来源已完整接入。

### 分层同步

| 对象 | 规则 |
| --- | --- |
| Campaign池 | 每天完整同步已加入活动及商品，采集事实与资格筛选分开 |
| 高机会全托发现池 | 持续发现新品；具体扫描频率、分页范围和单轮成本待接口实测，不能把每日“全部详情重抓”写成已确认 |
| 已选商品 | 首次完整台账；自身选入/变更回执更新本地，任务涉及PID定向核验；低频完整对账发现外部变更，频率待测 |
| TapLink | 独立台账、使用关系、状态核查与清洗，不跟随每次货盘同步逐链重抓 |

已选商品由指定全托发现源选入。商品选入与TapLink创建是两个独立外部动作，各有幂等意图、回读与未知状态。复用旧版成熟的货盘筛选、分佣规则、批量选入/建链及历史台账能力，不复制旧服务或未经验证地沿用旧默认参数。

二发要求有达人佣金优势、Campaign剩余>45天，评分>4为偏好。**全托商品不要求库存数量，库存缺失、0或低于100均不因数量被拦截；不为库存单独发起读取或提前选入。** 普通或尚未证明为全托的商品保留库存>100要求。平台明确下架、治理、失效等状态仍拦截；已知暂时缺货标记不等同下架。价格带和内容形式暂不作为主要评价依据。字段缺失不能虚构成通过；不同Offer的佣金、活动与库存不得拼接。

## 5. TapLink创建、复用与清洗

### 创建纳入全量准备

1. 按市场、机构、PID、来源/活动、佣金方案版本确定需要的卡片材料；一个材料可供多位达人使用。
2. 查本地台账及平台现有列表，核实具体listId、成员PID、来源、活动、达人佣金、可用性和账号身份适用范围。
3. 仅对缺失的方案准备选入/建卡动作；新建一次后保存回执并回查。未知只核验，不创建替代意图。
4. 准备完成的材料必须能定位具体可用商品卡。仅有短名、拟佣金、建卡请求成功或一段URL均不能当作可发送。
5. 冻结正式/候补成员的材料引用与模板版本。发送前复核活动、佣金、绑定和平台可用性等动态条件，变化只影响对应成员/材料；全托不核验库存数量。

复用不能只按PID判断。换账号还要确认机构市场身份及该卡片可见/可发能力，不复制Cookie或签名状态。仍有效且已有使用记录的旧方案不能因新方案出现而自动删除。

### 清洗

目标：清除失效、减少重复、释放容量。删除TapLink、移除已选商品、本地停止新使用是不同动作。

明确整条列表失效，复查后才删除并回查；暂时缺货、混合有效列表、状态未知不当作可删。有效且已发送、已加橱窗，或使用情况未知的链接默认保留。重复需核对活动、佣金和使用关系。清理后容量仍不足，列出有效旧链接交人工决定。历史和删除意图保留；未知删除不重复执行。

## 6. 发送与回复阶段调度

- 按机构×市场独立调度，多个账号共享任务与平台新联系额度；不同市场可处于不同阶段。
- 每日新达人500为用户确认业务口径，重置锚点仍需平台证据；登录账号数量不增加该额度。
- 未解锁新达人最多5条我方消息，商品卡计1条；达人回复或有有效加橱窗证据后解除这两类新联系限制。月度消息额度会刷新，具体重置语义待实测。
- 新额度满后继续符合条件的已解锁达人；达到任务目标、窗口截止、无可发送合格线索或对应平台限制时结束本轮发送。
- 定时默认北京时间，展示市场当地时间。截止时间可跨午夜。窗口结束不再提交新消息，在途进入核验；原任务保留跨日进度，累计完成N人后结束。
- 同机构市场默认旧任务优先，新任务排队，允许人工调优先级。优先级不打断在途动作，不绕过准备和时段条件。
- 账号异常自动选择同机构市场已核验可用账号处理未提交线索；未知不换号重发，无可用账号或范围级限制才暂停相关工作。
- 发卡→回查→文字→回查；组件持久化，重启先核验既有意图。若卡后咨询导致宣传文字取消，保留单卡和咨询事实，不能伪称完整发送。
- 发送期间持续收信，咨询停止该达人未提交推广；拒联即时生效，其他达人继续。自动答复等待回复阶段，包括人工接续确认句。
- 关系Agent使用既定业务策略和实际可用工具；额度/状态机/重发控制由程序负责。人工暂停回复优先于所有自动阶段切换。

## 7. 界面

沿用TailAdmin Next.js免费MIT基础，保留来源许可，不引入Pro。日常页面不暴露数据库、脚本、研究批次和调试字段。

- 货盘：商品源/同步、全部/筛选货盘、分佣规则、已选商品、TapLink准备与清洗；分别显示最新同步、覆盖与缺口。
- 达人库：保留旧版GMV/粉丝/类目/联系方式/标签/MCN筛选，批量标签、人工资料、完整详情与维护能力。主列表一人一行，增加合作状态/最近联系；缺数据不是0。历史别名、来源与PID线索进详情。不同机构关系隔离。待解析handle进采集记录。
- 合作工作台：一发/二发分开，默认二发任务列表；自然语言＋表单创建，任务卡确认。
- 二发任务详情：目标、正式/候补准备、TapLink就绪、发送计划与阶段、完整完成量、部分/失败/未知、下一次执行、异常；速度用曲线，目标完成率=count/N，卡片成功不冒充完整触达。
- 账号管理：机构市场身份、登录/能力/维护状态、当前用途及异常；正常分配自动完成。
- 收信和人工待办保留；AI回复暂停状态明确，不能在营销任务成功后静默打开。

## 8. Agent与上下文

任务解析Agent只输出结构化任务建议，产品经理确认后冻结。确定性批次调度器执行阶段与配额；商品语义能力按商品缓存短名；一个关系负责人协调某达人的上下文，按需读取现有业务工具/Skills，不安排多个Agent反复转述同一会话。

长期事实存自控数据库。模型只取当前任务范围、必要商品事实和相关近期消息；原消息不全量塞入prompt。工具结果含来源、观察时间、权限和未知语义。商品名称或达人原话不作为工具调用指令。运行日志展示当前阶段/数量/具体异常，技术追踪折叠。

## 9. 验收

1. 指定唯一全托来源可持续采集新增PID，完整性与字段证据明确；这是上线硬条件。
2. 可创建3000/5000固定目标任务，正式＋候补完整准备后才放行；TapLink缺失/未知能真实阻塞准备。
3. 一次任务确认后自动执行、跨午夜/跨日续发、优先级排队、账号故障切换；不能混淆机构市场额度。
4. 拒联/咨询及时停止对应推广；发送/回复阶段不并发外发，人工回复暂停始终生效。
5. 目标不超计、不重发，单卡、拒绝、未知分开；备用只替换明确不能发的项。
6. 速度曲线来自真实完整确认；20位/分钟是吞吐目标，必须以持续真实样本验收。
7. 旧版达人库和货盘成熟能力承接；字段覆盖、用户操作、性能与恢复分别验收。
8. 旧项目不改写、不恢复旧暂停试点、不删除有效旧资料。

当前实现进度见[批次架构与实施顺序](architecture/batch-outreach-v2.md)，不能将本PRD当作全部功能已完成。
