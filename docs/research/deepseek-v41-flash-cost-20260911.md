# DeepSeek-V4.1-Flash 匹配费用测算

核对日期：2026-09-11。用户要求把前一版占位价格换成 DeepSeek 4.1 Flash 测算。本轮只查询公开文档和计算，没有读取密钥、调用付费模型或更改运行模型。

## 1. 官方型号与价格

官方当前版本为 **DeepSeek-V4.1-Flash**，API 模型名 `deepseek-flash`。下面为官方人民币价格，单位为每百万 token。

| 计费项 | 空闲时段 | 高峰时段 |
| --- | ---: | ---: |
| 输入，缓存未命中 | ¥1.00 | ¥2.00 |
| 输入，缓存命中 | ¥0.02 | ¥0.04 |
| 输出 | ¥4.00 | ¥8.00 |

高峰：北京时间周一至周五09:00–12:00、14:00–18:00；其余为空闲时段。后续价格以[官方价格页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing)为准。本表不用汇率换算，也不包含其他模型的价格。

## 2. 保持相同工作量假设

- 商品每日语义变化2%，达人1%；只有其中10%需模型特征提取，每次600输入＋100计费输出。
- 每次关系匹配及首轮文案决策：1,200输入＋200计费输出；关系决策另计10%重试/作废重工。
- **基础表按无输入缓存、短输出场景计算。** 适用于非思考模式的规划预算；不能直接当作默认思考模式的实测费用。
- 每日轮次是进入模型的判断数，可能决定不发，不是平台允许发送量。没有每日全库重新匹配。
- 本次只计算 Flash 的 LLM 部分；向量模型、后续多轮咨询、视觉模型、第三方采集、主机和人工另计。

## 3. 日费与30日预算

| 商品 / 达人 | 每日关系决策 | 日输入 / 输出 token | 空闲价/日 | 高峰价/日 | 30日预算 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1,000 / 10,000 | 500 | 667,200 / 111,200 | ¥1.11 | ¥2.22 | ¥33.36–57.82 |
| 5,000 / 20,000 | 2,000 | 2,658,000 / 443,000 | ¥4.43 | ¥8.86 | ¥132.90–230.36 |
| 10,000 / 50,000（压力假设） | 5,000 | 6,642,000 / 1,107,000 | ¥11.07 | ¥22.14 | ¥332.10–575.64 |

30日按22个工作日＋8个周末、每天同样工作量测算。下端全部使用空闲价；上端工作日全部使用高峰价、周末使用空闲价。实际日期和token发生时段不同，账单会变化；没有把周末也错误算作高峰。

中档无缓存算例：

```text
空闲日费 = 2.658 × ¥1 + 0.443 × ¥4 = ¥4.43
高峰日费 = 2.658 × ¥2 + 0.443 × ¥8 = ¥8.86
30日上端 = 22 × ¥8.86 + 8 × ¥4.43 = ¥230.36
```

首次语义特征提取是另一笔一次性成本：按10%实体需提取的相同假设，小/中/大档分别为 ¥1.10–2.20、¥2.50–5.00、¥6.00–12.00。仍不含向量，不叠加成每天重复开销。

## 4. 思考与缓存的敏感性

官方[思考模式文档](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode)明确：思考默认开启，effort 默认 high。OpenAI格式接口可通过 `thinking.type=disabled` 关闭思考；这是预算方案的可选设置，本轮未接API验证匹配质量。

如果中档每次关系决策额外产生1,000个计费输出 token，包含10%重工后的2,200次调用，会增加220万输出 token：

- 空闲价：**¥13.23/日**，约¥396.90/30日。
- 工作日高峰、周末空闲：高峰日**¥26.46**，约¥687.96/30日。

不能只数可见文案。思考＋工具调用还可能增加后续请求输入：官方要求携带tools的历史相关消息完整回传reasoning_content。需要按实际usage和每个子调用累加，不能在这种多步调用中仍假定始终只有1,200输入。

缓存按**命中的输入token比例**计费，不按“多少请求命中”计算。以中档50%的输入token命中为假设，短输出日费为空闲¥3.13、高峰¥6.26。官方[缓存说明](https://api-docs.deepseek.com/zh-cn/guides/kv_cache)表示缓存默认启用、需完整匹配已落盘的前缀单元，且为尽力而为；不保证某个比例。

建议将通用指令和稳定结构放在公共前缀，读取 `usage.prompt_cache_hit_tokens` 与 `prompt_cache_miss_tokens` 校准。不要为了凑缓存增加无用上下文。主动批量研究可考虑空闲时段；正常服务时效和发送前事实复核优先，不能为省费延误达人请求或发送陈旧方案。

## 5. 复算入口与验证

```sh
node scripts/matching-budget.mjs --model deepseek-flash
```

`estimateDeepSeekFlashBudget()` 返回明确的 `CNY`、日输入/输出、缓存命中、额外思考、日费及30日场景；不混用原工具的 `costUsd`。不带参数的旧入口仍是明确标注的通用占位测算。

已独立复算三档日费、缓存分摊、额外思考输出、30日时段组合、零工作量与非法参数。Token数仍为工作量假设，并非 DeepSeek tokenizer 或真实任务测试结果。
