# TailAdmin Next.js 界面设计执行稿

T03 已被明确选为 BDHub-Agent 的界面基础，使用者已进一步选择 **免费 MIT 版＋自行实现缺少页面**。当前 `apps/web` 已完成七路由可操作前端原型：[打开今日经营](http://127.0.0.1:5198/overview)。模板固定为 Free 2.3.0 / `d3526b35fb7e579a4585129fe6eaa47f54ec9a0b`，未引入 Pro 源码。来源见[许可核对](../../research/tailadmin-license-review.md)和[页面映射](tailadmin-page-map-20260911.md)。

原型中的流程与状态使用示例数据模拟；下文同时保留真实系统的设计目标。真实数据库、模型、连接器、认证与持续执行尚未实现，不能把界面中可点击的模拟能力视为生产完成。

## 1. 设计目标与继承范围

沿用 TailAdmin Free 的应用壳视觉、导航尺寸、表格、按钮、主题切换和图表表达，使用其源文件中的统一 tokens。实际导入主题 CSS、基础 UI、图标、ThemeContext/ThemeToggleButton 与示例素材；应用导航、中文业务表单、关系会话和共享弹层自行实现，逐文件来源见 `apps/web/TAILADMIN-SOURCE.json`。

改变的是业务内容与任务组织：以经营目标、机会、达人关系、具体决定和真实结果为中心。不能直接把模板的 Orders/Revenue/Customer 改个中文名字，就称为 Agent 系统。模板中收入、套餐、无关行业仪表盘和生成器页面不自动进入产品。

不继续此前被否定的生成图风格。中文排版补充与密度在第一份基于真实模板的中文页面中验证；不先创作另一套色彩、图标或阴影系统。

## 2. 信息架构

下列是当前原型采用的导航分组。PRD 的14个功能视图分布在七个入口及详情中，不做成14个一级菜单。

| 常用入口 | 页内视图 / 详情 | 默认任务 |
| --- | --- | --- |
| 今日经营 | 已推进、系统处理中、需要决定；目标与关系下钻 | 打开系统即知道现在该处理什么 |
| 经营目标 | 运行中、草稿、历史；策略编辑与影响预览 | 给 Agent 一次明确经营目标和允许范围 |
| 机会与货盘 | 二发线索、一发匹配、商品/Offer、待准备 | 看值得推进的机会和具体依据 |
| 合作工作台 | 关系会话、商品事项、样品/链接、需要决定 | 接续当前诉求并管理一人多事项 |
| 效果与质量 | 经营进展、人工时间、费用、评估与运行 | 判断系统是否确实带来有效合作 |

低频入口：Agent 与知识（职责、工具、Skills、话术、参考案例、MX 历史）以及系统设置（账号/连接、资源、人员、迁入）。全局搜索、市场、待处理决定和个人菜单沿用模板的通用位置。登录页仅作为身份入口，不从演示表单推定真实认证已完成。

## 3. 关键页面结构

### 今日经营

以免费版指标卡、统计图表与列表的视觉组织自建 `/overview`。首屏显示新增有效覆盖、合作进展、需要决定和等待信息。正常等待与技术故障分开；数值当前来自演示模型。

主区域是正在推进的经营目标和合作动态。具体决定能直接打开对应关系/事项，不要求运营从日志重查。每个数字都能展开分母、窗口和来源；没有收入归属时显示缺口，不展示模板默认收入。

### 经营目标与策略

列表按运行/草稿/历史分组。新建流程连续完成：输入目标 → 确认市场和货盘 → 确认允许动作/商业条件 → 查看代表性消息与影响 → 启用或保存草稿。使用模板现有表单布局和控件，不新增复杂画布。

每次策略调整保存版本；影响预览区分新候选、尚未发、在途和已有承诺。暂停按钮必须让人区分“停止新获客”和“停止全部自动外联”，不能只改状态标签。

### 机会与货盘

使用免费 Table/Badge/Button 基础自建筛选、分页和商品/机会视图。商品行组织市场、PID、具体 Offer、有效期、来源和准备情况。二发展示带货依据与准备情况；一发展示匹配依据和画像缺口。真实发现游标、覆盖计算和在线画像更新属于后续连接器工作。

选中候选后打开详情抽屉：为什么值得联系、尚缺事实、已有关系/其他机会、本次下一步。正常主动作是进入经营计划或关系处理，不在每行堆一个立即发送按钮。

### 合作工作台

自建关系列表、会话与证据区域，沿用免费模板的视觉 tokens 和基础组件。左侧按关系/待处理事项排列，中间原文与中文辅助理解，右侧显示当前商品、条件、下一步和证据。会话布局未复制 Pro Chat 或 Support Ticket 源码。

多事项以页内标签或列表切换；一条达人消息可以更新多个事项，但同一关系保持一个有效外联控制。人工接管后正文输入变为人工可编辑，AI 待发稿失效；已提交/未知动作继续显示并核验。交还后重新判断，不能直接续发旧稿。

### 具体决定

使用详情/弹层组件，固定显示：对方要求、已查事实、可选方案、费用/交付影响、推荐及作用范围。决策提交后显示真正的状态变化和待处理部分。正常查询和明确官方样品路线不进入审批队列。

### Agent、话术与知识

自建职责、话术、知识历史和离线回放四个页内视图，内容围绕关系 Agent、程序调度/执行、按需专业任务与评估流水线。不能为了展示模板卡片又恢复固定多个自治人格。

话术编辑提供固定正文、骨架改写、策略生成；三市场预览、依据、正文与译文可比较。知识页分当前规则、参考案例与历史接续。MX 历史四类是并列分类，不能画成顺序进度或直接触发群发。

### 效果与运行

使用模板图表、表格、连接与通知样式。经营指标和基础设施状态分别展示；工具未连接、数据过期、等待、明确失败和未知结果有不同含义。按市场/策略/来源比较，不跨币种简单合计。

## 4. 三条必须走通的交互路径

| 路径 | 连续动作 | 完成证据 |
| --- | --- | --- |
| 二发主干 | 目标 → 商品/带货线索 → 同人归并 → 个性化消息 → 回复 → 有效卡片/方案 → 结果 | 触达、平台接收、采用和合作进展分开，能回到同一关系 |
| 一发匹配 | 商品 → 适配达人及依据 → 一次邀约 → 申请/入口问题 → 样品/链接事项 | 不重复索取已知信息，不把推荐或等待算成功 |
| MX 历史接续 | 历史候选 → 当前事实核实 → 已解决/过期/可行动/不明 → 当前事项 | 导入不发送，确认仍有效才生成新的当前判断 |

设计原型阶段可使用模拟数据验证导航、表单、状态和关系一致性；必须显著标为演示，不能假装有真实模型、平台或生产授权。

## 5. 组件和状态验收

每个核心控件要有默认、悬停、焦点、禁用、加载、空态与错误态。表格需要全页/全筛选范围区别、分页和已选范围反馈；表单需要必填、冲突和保存失败；会话需要生成中、被新输入取消、人工控制、在途与结果未知。

组件样式以固定免费 TailAdmin 源码为准，复制的免费组件保留版权许可；第三方图片/字体/库分别保留来源。原型使用共享模拟状态验证跨页面交互，界面显著注明演示；本机 reducer 和 localStorage 不冒充真实 API 或生产数据库。实际视觉、交互与剩余验收缺口见根目录 `design-qa.md`。

## 6. 当前完成与后续实施

免费模板与版本已固定；应用壳、中文今日经营、经营目标、二发/一发/货盘、合作与决定、知识历史、话术和结果已在同一演示模型中贯通。逐页面范围见[页面映射](tailadmin-page-map-20260911.md)，可操作流程见[前端说明](../../../apps/web/README.md)。

下一步依据使用者对原型的反馈调整业务流程，再按 PRD 的小闭环计划接入自控数据、只读事实和受控执行。真实模型回放、平台能力、耐久任务、商业授权与结果归因各自验收。前端技术栈已经确定，不因此提前决定 Agent 运行框架或服务器部署方案。
