单一主类目是旧导出的有损归一结果，没有原多类目或当时归一器版本。当前旧代码的`mx-canonical-v1`不能倒推成当时官方版本。价格带、视频/直播数量仍为空；不从GMV、粉丝量或关联商品价格补值。

## 结构验证

原始聚合记录：[italy-first-profile-validation-20260912.json](../research/italy-first-profile-validation-20260912.json)，不含达人handle、OEC或联系方式。

- 19,890种理论组合中，四款商品对应550个同顶级标签组合。这只是研究候选，不是准确匹配。
- 5个商品方向＋25个类目代表的达人方向，共30次首次查询和30次缓存查询。每路最多200，最终每次最多50，界面默认20；实际检查200个唯一候选、双向204次展示。没有做随机对照、全量人工评价或留出集实验。
- 首次查询P95为4.161ms，缓存P95为0.936ms；这是本机同步小样本，不是磁盘冷启动或服务并发容量。
- 为四款商品各准备1份关系资料，实际2,543–2,556字符，保留分类来源和未知控制；均低于6,000字符。字符不等于DeepSeek token。
- 同品边、Offer和需求记录均为0；不按handle关联上轮48位Kalodata达人，不从旧销量、排名、GMV或原短名单派生排序特征。商品范围仍沿用先前五商品研究，不宣称样本选择无偏。
- 人工标签全空、适配比例为null；模型调用0、计费token 0、真实发送0。

## 人工评审

候选中的“人工判断”支持“适合继续研究／不适合／资料不足”、理由、保存及撤销。问题是：根据展示的历史资料，是否值得继续研究。它不判断发送资格或成交结果。

评审绑定数据集、召回指纹与商品—达人组合，保留版本和时间。同请求重放不重复保存，并行编辑检测版本冲突。事实、特征或算法版本变化后，旧标注保留但不计入新召回；目前按召回快照隔离，不静默合并不同查询方向的标注。

中断请求恢复成功后，通过只读接口恢复原有效召回及最新评审；读取失败显示“判断已保存，恢复评审上下文”，不重发保存。页面再次刷新保留待恢复runId，标签正文始终留在数据库。原run过期时保留历史判断、重新召回，不把旧标注计入新版本。

统计仅涵盖当前返回候选：覆盖率＝已评审／当前候选；人工适配通过率＝适合／（适合＋不适合），分母为0显示“尚未评估”。未评审和资料不足都不算负例。当前没有可靠人工正负标签，不能计算推荐准确率。

本轮没有替使用者预填判断。保存、清除、重放、竞争和重启测试使用隔离的合成资料，真实库等待实际评审。本机尚无多人身份认证，评审不作为可识别多位审核者的生产审计。

## 实现与复现

三份旧文件由脚本直接读取：`data/research/product-exploration/it-global-sales-pilot-20260910.json`（商品、明确EUR价格）、`data/research/product-exploration/pe_c0e628110f1a42bc9d9477ff2dec464f.json`（精确PID分类详情）、`data/research/outreach-ai/runs/oa_f9a4f4af84f3142fc119664a82de4be5/creator-snapshot.json`（OEC、handle、主类目和原观测时间）。来源SHA-256见聚合报告。

在`apps/web`执行`npm run import:italy-profiles`。固定写入新项目`var/matching-italy-profiles.sqlite`；重复导入3,983条事实不新增、不更新。源指纹或对齐版本改变时拒绝覆盖，先明确新版本。批量验证另建临时库，完成后清理。允许字段与本地报告留在`var/`，不进入Git。

`CategoryFact`与实体主来源分开保存：状态、原标签路径、命名空间、变换版本、时间依据和引用。层级顺序保留；不同命名空间不能只因字符串相同而匹配。商品分类时间是采集批次完成时间，不是行级更新或商品销量窗口。元信息进入模型资料与缓存指纹。

API新增本机人工评审保存及有效召回回读，没有发送动作。人工“适合”不会改变拒联、人工接管、暂停或执行权。算法版本`structured-recall-v3`使旧缓存失效，原记录不删除。核心代码为`italy-profile-import.ts`、`italy-profile-evaluation.ts`、`category-facts.ts`、`store.ts`和`AssessmentPanel.tsx`。

下一步先形成有理由的实际评审，并明确哪些过期字段须补采；再按达人分组建立留出评估，对比结构召回与语义补充。具备参考判断后，以少量DeepSeek-V4.1-Flash调用测量实际usage和失败情况；日预算、模型接入与远端采集本轮未启用。
