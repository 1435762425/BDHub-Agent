# 意大利二发试点与本地预演

2026-09-12。已有画像分析已完成后，本轮继续意大利二发：精确同品证据→按达人归并→意大利语稿件→冻结→本地模拟队列→原回执核验→结果台。

入口：[二发工作台](http://127.0.0.1:5198/workspace?mode=second)、[预演结果](http://127.0.0.1:5198/results?mode=second)。当前模式严格为`dry_run/local-simulator`，真实发送0。使用者此前明确“不真实发送”；这次“实测”是否升级为真实发送已提出边界问题，截至本轮记录未取得新范围。不会将本地预演称为平台发送验收。

## 已实现与实际测试

- 5商品、48位Kalodata来源达人、50条精确PID正销量边，生成48个关系机会和48条意语稿件；2位达人各2款商品合并为一条文本。
- 稿件182–231字符，使用有版本的确定性程序生成，尚未调用模型。只探询合作兴趣、提出继续核对可提供条件；不声称看过视频、持有实物、已开商品卡，不承诺佣金、免费样品、库存或发货。
- 冻结快照保留完整正文、正文哈希、来源指纹、本地控制版本和真实资格缺口；每个意图只有1个文本组件，没有伪造商品卡。
- 全部48个案例分别跑正常接收、接收后回执丢失、提交前中断三组隔离测试，共144次持久提交尝试，其中96条模拟器回执。正常组48接收；丢回执组48经原回执核验接收；提交前中断组48保持未知且回执0。全部尝试均为1，无盲目重发。
- 展示库保留48次尝试、47条模拟接收和1条预期未知故障用例。对未知用例查询不到原回执时继续保持未知；这不是“确认未发送”。
- 重复导入48条均不变化；重复预演跳过47个已完成、1个未知，提交次数仍48。暂停不误恢复；来源更新取消的尚未提交记录可按新版本重新冻结，完成/未知记录不能借换ID绕过去重。
- 全154项自动测试、TypeScript和生产构建通过，包含两Worker争抢、租约到期旧Worker写回、提交前后崩溃、控制竞争与API拒绝真实模式。核心测试实际发现并修复了数字ID被JS隐式转为字符串的精度风险。

聚合证据：[italy-second-pilot-validation-20260912.json](../research/italy-second-pilot-validation-20260912.json)。报告不含达人handle、OEC或私信正文。当前结果不是成交、采用、回复、平台送达或模型效果。

## 实现与复现

独立库：`var/second-italy.sqlite`，与画像库、二发证据库、原三人演示runtime分开。旧`LocalRuntime`含示例佣金、示例卡和索卡入站，不适合直接承接真实来源；本轮复用其不变量，新增类型明确的二发切片，没有导入那些假商业条件。

核心代码位于`apps/web/src/server/second-pilot/`，合同和界面在`features/second-pilot/`；`GET/POST /api/second-pilot`只接受本机来源。保存本地请求编号用于恢复，恢复结果会重新显示对应关系。

1. 在新项目根目录，用旧Python环境运行新脚本`scripts/export-italy-second-readiness.py`。脚本固定旧来源SHA与目标集，本机PG只读、REPEATABLE READ、15秒超时，只输出允许字段到新项目`var/`，不读取/导出私信正文或凭证。
2. 在`apps/web`执行`npm run pilot:italy-second -- --rehearse`。它读取已存在的`var/italy-offline-batch.json`与准备调查文件，生成稿件、先跑三组临时库测试，再按状态续跑本地预演。无参数时只导入并测试，不排新模拟意图。
3. 执行`npm run second:worker`持续处理本地队列；`-- --once`只处理一步。Worker按脚本位置定位数据库，从项目根或`apps/web`启动都使用同一个库，不受cwd改变影响。

暂停仅针对本地实验控制，不更改真实接管/拒联字段。结果未知先核验原回执，缺回执不会成为重发依据。冻结和queue请求编号包含版本或快照；同一轮已完成机会不反复提交。此库是当前固定试点，不把该限制当作跨活动的永久去重；正式多轮合作需另设合作周期与执行归属。模拟故障用例保留是预期测试结果，不通过删除库来消除。

Web仍在127.0.0.1:5198，本地独立Worker不监听端口。本轮未安装LaunchAgent、未改旧BDHub服务、未启动任何真实发送、建链或审批。
