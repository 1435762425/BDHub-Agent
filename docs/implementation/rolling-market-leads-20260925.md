## 具体参数与取舍

| 项目 | 本批实现 |
| --- | --- |
| 请求片段 | 每次最多 3 个 HTTP 请求；一阶段最多 8 片段，然后让出资源并推进后续 |
| 轮转 | A/B 及各自断点/新到期侧的轮转位持久化；额度耗尽后优先回到原受阻类型的断点 |
| 刷新 | 7 天从冻结查询开始锚定，晚完成不无限顺延；已陈旧窗口完成后立即有新窗口资格 |
| 额度 | 市场独立等待，原任务每小时检查一次；接口未给出已验证重置时刻，不假定零点恢复，也不声称已测得准确周期 |
| 单 PID 技术失败 | 首次加后续尝试共 3 次；前两次退避 5/30 分钟，耗尽隔离；7 天后或材料实质变化重新评估 |
| 全局读取故障 | 认证/初始化等待 1 小时，锁忙 60 秒，服务端 5xx 等待 5 分钟；不计作每个 PID 的失败 |
| 旧 B 迁移 | 4 个已开始项沿原 generation/页；仅旧批次尚未读取的排队项在真正领取时冻结新窗口，原历史行不删除 |
| 已被新结果覆盖 | 本地精确对照更新的完整 generation，旧读取记 superseded，不继续网络请求，不把它改判原查询成功 |

片段数不是每日请求/视频数量上限。平台额度不足时，7 天是到期目标而非完成保证。B 沿用小量缺作者明确记 gaps 的合同；过多缺口只阻断该 PID，不能把缺口当成完整作者覆盖。
