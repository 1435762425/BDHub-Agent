# 新画像进入匹配分析

2026-09-12。达人库的新画像现已接入意大利画像分析。首轮精确更新原有 21 位达人，新增 11 位，匹配池从 3,978 增至 3,989；其余 3,957 位原始记录保持不变。入口：[画像分析](http://127.0.0.1:5198/opportunities?mode=matching&dataset=italy-profiles)，也可从达人档案点击“分析适合商品”。

## 数据如何同步

`italy-profiles` 的 matching API 每次访问前执行本机增量投影。读取身份库的追加观察，按 rowid 水位而非业务时间推进；默认一次最多 1,000 个事件。迟到事件不会被漏掉，但不会用其旧业务时间覆盖较新画像。身份库代际和首事件指纹用于发现换库、水位倒退；异常时保留已应用的匹配数据，并显示同步异常，不推进错误水位。

身份读取使用一致快照。相同观察时间下，完整 `:profile` 优先于 `:find-profile`，最后按 rowid 决定；不再按随机 event UUID 选取。本规则同时用于达人库字段展示，修复了现场一位达人误选简略 Find、把完整 Profile 已有字段显示成历史值的情况。

按市场/OEC 查找原匹配记录，保留原 ID、原始导入来源、人工控制、拒联和外部来源身份。新达人使用确定性的 `it-profile-oec-{OEC}` 匹配 ID，并登记到 canonical creatorId 的精确映射。未核验的 Kalodata 数据集不参与该同步，不迁移其同品边。

画像、映射、源水位和同步版本在同一个匹配事务提交。重复访问同一水位不会再更新版本、索引或重算队列。同步表惰性创建，未启用同步的其他数据集不被顺带迁移。

## 字段与统计口径

- 经营指标来自一份最新实际观察，不把历史平均播放补进新的销量/GMV统计组。0 是观测值，无值、缺失、未授权、错误保留为相应状态，分析数值为 null。
- 最新类目可用时采用最新具名类别。仅在当前类目缺失或未提供值时，允许沿用同 OEC 的历史类别，保留其原观察时间和来源；未授权、错误或既有分类冲突不能被静默解除。
- 命名空间沿用已核对的类目标签映射。新出现的 `Pre-Owned` 未被擅自翻译归类，保留源标签和未映射说明；不使用未知类目的权重做销量份额。
- 指标按来源统计截止时间分组，起始日未知继续标未知。首轮 29 位截至 9 月 10 日、3 位截至 9 月 11 日，与原 7 月 28 日组分开；没有截止时间时按 OEC 隔离比较组。
- GMV 只在来源明确提供 € 符号和精确十进制金额时标 EUR，不能仅由市场推币种。价格带和内容形式仍仅作参考，画像年龄不阻塞分析。

首轮 32 份投影中，3 位无可用类目，1 位单独保留历史类目，3 位有部分经营指标缺失。该计数描述首轮批次，不是整个 3,989 人库的数据缺口统计。

## 增量分析与旧版本

复用匹配器已有分区索引，更新达人时失效其旧、新类目分区及达人依赖。受影响查询按依赖判断，包含原结果之外新进入候选的人，不能只看旧候选里是否有更新对象。

只为每个查询的最新缓存版本保存待重算记录。每次 API 最多推进 3 个待重算查询，新 run 及替代关系另行保存，旧 run、资料包、人工判断和请求回执不改写。初始数据集 ID、来源及 importedAt 不变，同步时间与版本单列，避免无差别作废全部缓存。

画像分析页可见时每 5 秒检查同步状态。新观察使当前结果过时后，页面保留原结果和旧资料包，显示“按最新画像重新分析”；用户明确切换后展示新结果。旧版本的评审保存、资料包准备等仍按原门禁返回 `409 stale_run`，不会偷偷替用户换版本。关闭页面时不新增匹配常驻进程，下次访问 API 再追上水位。

## 实际验收

先以原匹配库的独立备份做投影验证，再应用到新项目当前画像匹配库。备份位于 `var/matching-profiles-before-registry-sync-20260912.sqlite`，不进入 Git。

- 首轮：更新 21、新增 11、未动 3,957，32 个 canonical ID 均精确映射；初始 2 个受影响缓存查询自动重算。
- 查询：32 次达人方向、5 次商品方向及缓存复查通过，生成 21 份有候选的关系资料包，最大 5,770 字符，未超过 6,000 字符上限。
- 页面实测：一位有 2 个商品候选的达人经 OEC-only 真实刷新成功，3 次业务请求、Find 0；源水位 74→75，同步版本 1→2，累计 8 个缓存查询被重算，剩余待重算 0。
- 此次新观察的统计截止日和销量更新，未返回的平均播放保持 null，没有拿旧数值补新统计窗口。旧 run 和资料包 SHA-256 不变，旧 run API 返回 409，新包使用不同 ID、4,736 字符；页面可同时查看新包和历史包。
- 产品、Offer、同品证据、需求、初始数据集、人工标签和请求回执不变；二发匹配库与二发业务库原表哈希不变。没有真实消息发送或模型调用。
- 218 项 Node 自动测试、TypeScript 和生产构建通过。未改 Python 采集逻辑，本轮未扩大重跑其无关单元测试。

这是当前 32 份新画像与 5 个商品的本地分析验收，不是所有 3,989 人重新生成资料包，也不宣称已验证合作意愿或商业转化。首轮和页面增量回读保存在 `var/registry-profile-sync-run-report.json` 与 `var/registry-profile-sync-live-validation.json`；公开聚合见 [validation](../research/registry-profile-matching-sync-validation-20260912.json)。

## 运行与复现

正常打开画像分析页即可自动应用新观察，无需额外 Worker。原 `npm run identity:worker` 仍负责按需抓取，匹配同步本身不访问平台。

在 `apps/web` 手动追上当前水位并运行有界分析验证：

```sh
npm run sync:identity-profiles -- --verify
```

旧 `import:italy-profiles` 是初始历史批次导入工具，不应当作当前画像刷新命令；它的整批历史断言也不能拿来验收已含新观察的库。身份库更换、损坏或观察冲突需核对来源，不删除匹配库或原消息来解决。
