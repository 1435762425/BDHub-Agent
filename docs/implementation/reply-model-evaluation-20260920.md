# 意大利回复分类最终人工评测

日期：2026-09-20。范围：35 条本机真实意大利入站 turn；DeepSeek 与 TypeSafe Jev 使用同一五动作政策独立影子分类，人工逐条选择 provider 无关的标准动作。本文只记录聚合结果，不复制达人原文或凭据。

历史说明（2026-09-25）：用户已取消新方案中的 Jev；下文保留当时评测事实，不再作为启用 Jev/challenger 的建议。当前 V2 与后续优化见 [AI 回复方案](../architecture/ai-reply-optimization-20260925.md)，旧五动作分数不能外推新规则质量。

## 总体结果

| Provider | 正确 | 准确率 | 误自动处理 | 误转人工 |
| --- | ---: | ---: | ---: | ---: |
| DeepSeek | 28/35 | 80.00% | 2 | 3 |
| TypeSafe Jev | 22/35 | 62.86% | 3 | 1 |

“误自动处理”表示人工真值为 `human`，模型却选择其他动作；它是当前最重要的风险指标，不代表系统真的发送过回复。“误转人工”表示真值可由确定性动作处理，但模型选择 `human`。

两个模型动作一致 26 条，其中 22 条正确，一致结果准确率 84.62%。一致并不等于安全：一致结果仍有 2 条误自动处理，并有 2 条把 `no_reply` 错判为 `collaboration_ack`。

## 错误模式

- Jev 把 8 条 `no_reply`、1 条样品请求和 1 条人工事项判成 `collaboration_ack`，合作确认过度触发最明显。
- DeepSeek 把 3 条 `no_reply` 判成人工，另把 2 条 `no_reply` 判成合作确认；保守性较 Jev 好，但仍不能直接自动执行。
- DeepSeek 有 2 条人工真值被判为模板动作；Jev 有 3 条。这些都是自动回复启用前必须归零或被确定性守卫拦截的风险。
- 简短肯定词高度依赖上下文；仅按字面把 `Certo/Certamente/Ok` 归为合作确认会产生误判。

## 当前决定

1. DeepSeek 作为下一轮主影子分类器，Jev 保持 challenger/对照，不把 Jev 单独作为自动主分类器。
2. 不因双模型一致而自动执行；一致样本仍出现误自动处理。
3. `collaboration_ack` 继续人工审核，当前两个模型的精确率都不足以自动发送模板。
4. `link_usage` 因零真值样本继续人工处理。
5. 自动回复继续关闭。下一轮先扩大真实样本，重点补齐链接用法、拒绝/停联、佣金异常、多意图及简短肯定词，再重新评测。

以上决定不修改达人关系、案件、发送台账或平台状态。任何真实自动回复仍需要用户另行明确开启，并必须经过确定性资格、当前案件 revision、发送意图和回查门禁。
