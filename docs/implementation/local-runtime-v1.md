# 本地持久运行切片 v1

本轮范围由使用者确认：先实现本地持久化与可恢复任务，暂用示例数据，不锁定最终 Agent 框架。旧 BDHub 的代码、数据库、账号和服务保持只读。

## 本次边界

入口为 `/workspace?mode=local`，从“合作工作台 → 进入本地运行”到达。先验证三市场各一段示例关系的“已有实物 → 当前方案 → 文字/商品卡 → 原结果核验 → 等待采用”。原有七页的其他流程仍是浏览器演示，不会把它们静默迁为后台业务规则。

本地状态、入站原文、事实来源、行动组件、尝试、任务和上下文快照保存到新项目 `var/runtime.sqlite`。SQLite 是当前单机小闭环的 PoC 存储适配，Q04 正式运行框架、Q05 正式部署仍未决定。没有将新系统接入旧 PostgreSQL，没有购买服务器。

运行判断为确定性 Planner，平台为本地模拟器；没有调用付费模型或 TikTok/WhatsApp。传输模拟中的“已接收”只表示本地模拟平台记录，不是实际达人送达。

## 运行职责与接口

| 部分 | 入口 | 责任 |
| --- | --- | --- |
| 界面 | `apps/web/src/features/runtime/RuntimeWorkspace.tsx` | 查询投影、提交命令、展示状态与具体下一步；不在浏览器直接改变业务事实 |
| 应用接口 | `GET/POST /api/local-runtime` | 本机来源与结构校验、请求幂等、领域错误；不暴露 SQL、路径或任意工具执行 |
| 公开合同 | `apps/web/src/features/runtime/contracts.ts` | 关系、事件、证据、上下文、行动组件与任务的版本化读写字段 |
| 运行核心 | `apps/web/src/server/runtime/engine.ts` | 事务登记、关系控制、上下文、工作领取与结果回写 |
| 独立 Worker | `apps/web/scripts/runtime-worker.ts` | 从持久工作中逐步处理 plan/execute/verify/wake，写心跳；关闭页面后仍可工作 |

浏览器不是唯一状态持有者。Web 与 Worker 各自打开本机 WAL 连接；没有跨网络或模型调用持有长事务。未来接模型时替换判断适配，接平台时替换执行/核验适配；领域状态、授权校验和结果归属仍保留。

## 不能从原型照搬的语义

- 同人同品不是“一生只发一次”的去重键。重复来源事件和同一逻辑动作应去重；新的明确服务请求可以形成新的行动，不能被旧 `delivered` 布尔值永久阻止。
- “达人说已申请”保存为陈述，不推导成平台待审核。没有申请查询证据时保持需要查事实。
- 历史模式只保存原文，不改当前入站水位、不唤醒营销任务、不覆盖当前关系控制。历史核实与接续是下一独立切片。
- 文字和商品卡有不同的尝试与回执。未知组件不能靠重发核验，也不能用成功文字替它判成功。
- 控制、输入水位、策略及 Offer 版本参与提交资格；同一请求在更新控制后重入不得恢复旧草稿。
- 明确拒绝新营销与主动服务请求分开。交还 Agent 不解除拒联；新的明确服务诉求必须重新核对事实与授权。
- 稍后再联系在当前测试中压缩为 20 秒；唤醒仅重新核对，不自动发送催促。正式时长必须来自约定/政策。
- 页面中的事件类型由运营选择，是结构化测试夹具。自由文字不会被一个尚未接入的模型自动识别，不以本地状态测试冒充语言理解评估。

## 启动与恢复

在 `apps/web` 使用 Node.js 22.18 或以上（本轮环境为 26.7.0）：

```sh
npm ci
npm run build
npm run start
```

在另一个终端、同一目录启动后台处理：

```sh
npm run runtime:worker
```

Web 只监听 `127.0.0.1:5198`，Worker 不监听网络端口；本轮不安装 LaunchAgent 或开机自启。控制台关闭或整机重启后，重新运行上面两个进程即可读取保留的数据；是否配置开机运行另行按部署方案处理。

`BDHUB_AGENT_RUNTIME_DB` 可为隔离测试指定路径，Web 和 Worker 必须指向同一文件。默认只使用新项目自己的 `var/runtime.sqlite`。数据及 WAL 不进入 Git；不要删除数据库来“重试”未知动作。

## 验收范围

已完成 48 项自动检查：19 项原型状态测试、24 项 SQLite 运行核心测试、5 项 API 输入/本机来源边界测试。类型检查与生产模式构建通过。

实际进程/接口验证也已完成：

1. Worker 未启动时，通过 HTTP 保存 Sofía 原始事件及 plan 工作；关闭并重新启动 Web，原事件 ID、工作 ID 和 ready 状态均保留。
2. 启动独立 Worker，原工作形成一个行动，文字和商品卡各提交一次；重复相同请求 ID、重复来源消息 ID 都不增加行动。
3. Pedro 的文字为 accepted、商品卡为 unknown；同时关闭 Web 和 Worker 后重开，原行动/组件标识与各一次尝试保持。
4. 再次启动 Worker，未知组件没有被重发。通过核验命令读取原回执，两组件变为 accepted，提交次数仍为 `[1,1]`；重复核验请求使用相同 ID 返回重复结果。
5. 发现并修正了“已核验提交仍显示待处理”的任务收口问题；原 blocked 提交在回执确认后转 done，因旧 unknown 阻塞的计划复用原任务重新判断。

运行核心的故障接缝测试还覆盖：模拟平台接收后进程中断、实际调用前进程中断、租约过期的旧 Worker 迟到、两个连接争抢、调用期间人工接管、历史记录挤占上下文预算、后续服务不抹掉旧行动的采用证据。

本轮浏览器工具在旧连接失败页面返回 URL 访问限制，因此没有继续尝试绕过；新入口的实际界面点验及浏览器刷新后请求恢复仍待复验。构建与 API 恢复成功不代替这项验收。

可体验的结果未知场景：Pedro 的首张商品卡由模拟器记录接收后故意丢失回执；界面保持“结果待核验”。核验读取同一组件的模拟回执，不增加发送次数。其他关系默认按正常顺序完成文字与商品卡。

## 下一阶段

尚未实现生产身份/账号能力、真实模型判断、真实平台执行、历史数据导出导入、商业规则发布、多机调度、完整备份恢复与规模压测。这些不能由本地 SQLite 或一次恢复测试推导为已经完成。

当前三关系快照会读取本轮全部示例记录，关系投影仍有 JSON 聚合。它用于验证小闭环，不是大货盘查询接口；生产化需拆分可增长账本、分页查询、保留周期、毒性任务停止/人工处置和账号容量控制。没有用小样本吞吐推算日触达量。
