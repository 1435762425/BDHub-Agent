# A/B 线索与发送池排序模拟

日期：2026-09-20。用户确认两类线索及简单排序：A 类为最近 14 天明确出单，B 类为最近 30 天精确 PID 视频播放量 `>=1,000`；B 类同一达人×PID 只取播放量最高的单条视频，不求和、不计算播放速度。本文只使用合成数据验证确定性顺序，不读取真实业务数据库、不连接 Kalodata、不修改发送池、不发送消息。

## 1. 排序合同

```text
A 类整体在 B 类之前

A 类：达人×PID GMV DESC → units DESC → sourceRank ASC → PID ASC
B 类：代表视频累计播放量 DESC → 代表视频发布时间 DESC → PID ASC

同一达人×PID 同时命中 A/B：合并为 A，保留代表视频证据
同一达人多个位置：只有最高优先级位置占发送槽，其余等待
```

身份缺失、达人未结回复/人工接管、冷却、拒联和商品失效在排序后继续按既有达人级/商品级门禁分层，不能因播放量高绕过。

## 2. 合成数据覆盖

- A 类保存同一市场当前采集口径的数值 GMV；
- 多个 A 类位置先按达人×PID GMV，再按销量和 sourceRank 决定先后；
- 同一 B 类位置有两条达标视频，只取 26,000 播放的单条，不累加 12,000；
- 两个 B 类代表视频同为 26,000 播放，用发布时间决定先后；
- 同一达人同时有 A 类和 150,000 播放的 B 类其他 PID，A 类占发送槽；
- 100,000 播放但无 OECID，只能等待身份；
- 50,000 播放但达人有未结回复，达人级冻结；
- 999 播放和超过 30 天的视频不形成 B 类位置。
