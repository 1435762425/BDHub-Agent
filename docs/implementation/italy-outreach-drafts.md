# 意大利个性化邀约草稿

2026-09-12。当前阶段把已有画像匹配结果接入独立的草稿生成、审核与版本记录。模型适配已实现，实际使用仍关闭；本轮没有调用真实模型，也没有发送消息。

## 可体验的范围

在“机会与货盘 → 意大利画像分析”选择已关联稳定身份的达人，分析商品并整理关系资料包，即可看到“个性化邀约草稿”。支持自然友好、简短直接、适度详细三种表达，以及最多500字的单条补充要求。表达要求不会修改全局策略，也不能补成未经核实的商业事实。

启用模型后，单个任务先生成意大利语正文与中文辅助理解，再用一次独立调用检查全文、中文释义及依据。页面保存不同版本的正文、检查项、选中商品、事实依据、分阶段用量与费用。只能复制原文；机器检查通过不代表可发送。

当前仅支持 `italy-profiles` 中已映射到身份库的意大利达人、当前关系资料包和有同口径类目交集的商品。最多3件商品进入模型；已核对的意大利语商品简名来自现有5商品资料。不能把数千条历史画像全部视为已核验身份，也不自动把 Kalodata 二发记录按 handle 绑定到当前 OEC。

当前商品没有有效 Offer，因此这一能力仅探询合作意向。佣金、寄样、库存、价格优惠、发货时间、已有合作或看过视频，都不能由模型编造。二发的同品历史主张需要先完成跨来源身份和具体销售证据核验。

## 处理过程

1. Web只接受 `packetId/style/instructions/requestId`，服务端重新读取资料包、当前分析和稳定身份。客户端不能提供自己的事实包、模型、费用配置或发送参数。
2. 同请求编号先找原任务；原资料后来更新或模型停用，仍可读回已接受的任务。不同输入复用同编号会报冲突。
3. 上下文编译器提取少量事实，绑定资料包、分析、达人身份与业务策略版本。OECID、PID、来源路径等只留在内部绑定里。
4. SQLite事务预留试用名额与预算。Worker按达人协调，生成前重读当前事实；同一达人不会并行运行两个草稿任务。
5. 生成调用前持久记录尝试，收到响应先保存回执，再校验正文；生成成功后重新核对上下文，才进行独立审核。最后保存前再核对版本。
6. 审核不仅检查生成器提供的引用，还检查整个意语正文、中文翻译和选择理由。发现不支持的承诺、引用不符或语言问题，结果为 `needs_review`。
7. 原稿、原事实与费用不随新画像改写。按稳定达人身份可读取已保存草稿，不依赖当前标签页保留旧资料包。

画像年龄仍不影响结构化分析。“资料过时”在草稿任务中指绑定版本已变化、关系控制变化或身份不一致，并不是重新引入按画像年龄拦截分析。

## 上下文与业务 Skill

编译器输出分为内部 `binding/productBindings/evidenceSources` 和模型可见 `modelFacts`。模型只收到后者：当前 handle、表达要求、商品意语简名、类目交集、具名事实和“商业条件未验证”。不传完整画像、粉丝/GMV、联系方式、消息历史、账号认证或原始平台响应。

高频匹配继续由本机索引完成，不逐个商品与达人调用聊天模型。生成与审核共享稳定的业务策略前缀，按固定顺序序列化事实，不把任务时间和内部审计编号塞进提示词；缓存是否命中仍以服务商回执为准，不能预先把节省算成已发生。

业务能力定义在 `apps/agent/skills/it-intent-invitation/v1.md`，这是产品 Agent 的版本化能力，独立于开发用 Codex Skills。当前场景是 `explore_interest`。Skill哈希进入上下文指纹，策略更改会使尚未执行的旧任务失效。

生成和审核是两个有界阶段，不维护两个互相聊天的长期Agent。关系身份与任务由代码固定；语义表达交给模型，独立审核作为质量流水线。不存在自动发送或修改商业条件的工具。

## 用量和预算

Provider固定官方 `https://api.deepseek.com/chat/completions`、`deepseek-flash`、关闭思考、JSON响应，每次最多1200输出Token、24000字节输入和60秒总耗时。不自动重试或跟随重定向。

模型费用配置是新项目的 `var/outreach-model-policy.json`，缺文件默认关闭。当前最多3稿、总额¥1是待确认的小样方案，并非已启用的业务预算。每条任务预留¥0.25覆盖生成与审核；事务控制预留、已发生费用与名额，不靠浏览器按钮限制。

凭证只在请求时从进程环境或旧项目的官方 DeepSeek 配置读取到内存；不复制到新项目、提示词、命令参数或日志。当前运行暂复用旧项目Python依赖环境，正式独立部署仍需独立环境及凭证配置，不能称已完全脱离旧安装。

原始用量分别记录输入、缓存命中/未命中、输出、推理和总Token；推理Token已包含在输出Token内，不重复收费。未返回的字段保持未知。费用是对应报价版本与时段乘以实际用量的估算，不是服务商账单。跨时段报价不完整时保留上界与预留，并停止后续审核；目前没有自动账单对账。

具体报价、凭证选择及Provider验证见 [DeepSeek适配研究](../research/deepseek-draft-provider-20260912.md)。

## 恢复与结果

| 情况 | 持久化行为 |
| --- | --- |
| 请求尚未提交就失败 | 明确为未请求；释放未使用的预算与名额 |
| 已保存生成回执后进程退出 | 恢复原回执，只接续尚未执行的审核 |
| 两阶段回执都已保存 | 从原回执收尾，不再调用模型 |
| 提交可能已发生，但无完整回执 | `result_unknown`；不重发，保留名额与预留 |
| 返回usage缺失或不一致 | 不按零费用计算，保留记录与预留 |
| 资料在生成前更新 | 零模型调用，标记原任务过时，释放预留 |
| 资料在生成后更新 | 原文与费用保留，不用新事实悄悄改写旧稿 |
| Worker失去租约 | 旧Worker不能覆盖新拥有者的记录 |
| 审核通过 | `drafted`，仍是 `executionBlocked=true` |

机器审核也可能漏检事实或语言问题；本轮只有模拟响应测试，真实意语质量和模型遵循效果尚未验收。不会将FakeProvider的通过结果写成真实模型质量结论。

## 运行

```sh
cd /Users/bjn00003/BDHub/BDHub-Agent/apps/web
npm run drafts:worker -- --once
```

去掉 `--once` 可持续消费队列。仅启动Worker不会启用模型配置。本轮只运行了一次空队列验证，没有安装自启服务，也没有启动草稿常驻进程。Web预览继续使用 `npm run build` / `npm run start`；已有画像采集Worker独立运行。

持久数据独立放在 `var/outreach-drafts.sqlite`，不会写进旧业务数据库或覆盖二发模拟回执。政策启用与真实费用小样等待使用者已提出的选项答复，不能从“继续开发”或默认配置推导启用。
