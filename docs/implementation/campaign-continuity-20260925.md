## 行为与合同

- 新申请逐项处理，普通未知跳过该项继续，超过 100 项仍推进下一批。登录、账号门禁、平台验证等明确账号故障停止继续提交，记录账号阻断；不把它当作普通拒绝或没有合格活动。写入前保存实际请求 JSON，未知不改意图、不换账号、不重新 POST。
- 已加入活动采集/筛分不受新申请未知或失败阻断，加入故障单独保留在 generation scope/payload。已加入来源仍须完整分页、筛分落库；读取失败不以空快照覆盖或触发绑定退役。未知活动缺席保护其原活动/已返回子活动的既有绑定，已观测的佣金变化仍正常等待刷新。
- 有待核验项时，在 catalog 阶段内先通过原 TapLink 准备器处理已确认材料，再核验；最终来源和缺口一起发布原 catalog generation。新增确认时重读完整已加入商品范围，随后正常 TapLink 阶段幂等复用已准备材料。这里复用完整快照采集器，会增加一次列表/商品读取，不宣称是平台增量接口；已完成的加入和建链不重写。
- 首次核验加最多三次补查、整批共享 300 秒墙钟截止时间。从首次专项核验入口计时，初始化、锁等待、分页、请求、验证都包括在内。专用 CLI 用可清理的 SIGALRM 中断阻塞读取；每轮请求前持久记次，重启沿原截止时间/次数继续。一次轮次可能含多页，单项不会各获得 300 秒。
- 耗尽后保留 unknown、原意图、已用次数和停止跟进状态；不建人工任务或后台专项轮询。普通预览顺带看到原活动/返回子活动已加入时可自动结算。单次手动核验共用相同终身预算，空队列或已耗尽不访问平台。
- Web 区分“有限核验”与“已停止跟进”，不再提示必须逐项手动回查；累计活动行数不再受错误的 400 条门槛影响，CLI 响应仍受字节数限制。意外错误不向页面转发原始异常文本；已知结构化错误码保留。

## 数据与兼容

`campaign-join.py migrate --market <market> --confirm` 为原条目表添加五列：`request_json`、`verify_attempts`、`verify_deadline`、`followup_stopped`、`verify_error`。使用同一事务增量添加，重复运行无变化；旧库写路径缺列报迁移必需，status 只读兼容旧库且不创建不存在的库。历史请求 JSON 留空，原账号、子活动、原因和写入标记不改写。

状态读取使用 SQLite `mode=ro` 和一致读事务；本机同市场加入/预览/核验互斥，避免并行覆盖冻结意图。既有 IT 写门禁、非 IT 市场范围及持久业务授权未放宽；没有增加平台并发槽或 DELETE 权限。
