## 业务依据

使用者当前提供的文案是主依据，见 [MX参考记录](../research/mx-second-message-reference.md)。意大利三套固定表达保留同一条业务路径：再次推广给定商品 → 上方BJN商品卡 → 加入橱窗 → 后续视频或LIVE使用 → 若页面提供样品入口，再申请样品。

其他国家去掉WhatsApp和邮箱。返校季、八月、销量重新增长不能写死到其他商品或时间；当前版本不附加这些未经本次事实确认的段落。样品不是二发的资格硬条件，条件说明不等于承诺有样品或已经批准。

当前待定稿的固定模板版本3，ID保留为 `it-second-brief/choice/explore`，分别为标准、精简、视频与LIVE。模板内容在 `scripts/lib/second_templates.py`；仅填入核验称呼及已核对商品名，单复数链接表达按商品数量处理。每份稿明确 `requiresCard=true / deliveryOrder=card_then_text / requiredCardPids`，不能把“链接在上方”当成不发卡的纯文字。

墨西哥的历史TREND四分支、当前模板库中的种子例子、近期升佣网站群发是不同事实。历史三分支合计163条旧 `sent` 记录仅证明其曾被使用；本轮未联网重验它们。近期网站纯文字群发不能替代普通同品二发。

## 实测执行与恢复

`second_live_trial.py` 持有一个达人的账号、会话、租约和全部组件。一个试点最多3人，每人显式冻结1–4卡以及最后一条文字；1–4是容器上限，不是已开放的大规模发送参数。当前墨西哥界面默认最多2卡，新试点可明确选择1卡。

每张卡独立记录请求编号、attempt、候选回执与确认，所有前序卡confirmed后才允许文字。卡返回候选回执还不能解锁文字；原生类型、PID/list/Campaign、CID、OEC、sender、正文、client UUID、可见性均需匹配。卡成功后文字失败保留部分投递，不作为全部成功或从未发送。

建会话返回CID先持久保存，再进行608独立核验；核验前任何消息都被阻止。新owner恢复旧回执只允许读取，回查未找到或读取异常均保持未知，不重发。暂停和过期仍可核验原结果；已确认卡不再发送。当前campaign的未知结果和已确认收件人保留占用，换试点ID不能绕过去重；这是试点防重边界，不能推导为达人的永久营销限制。

`second_live_runtime.py` 使用账号既有只读mutex和现行MX `shared_write_gate` 的FIFO算法，间隔取当前账号策略，按远端sender ID共享新系统节拍。旧发送任务、出站队列、意图、组件/未决attempt及同sender旧gate都只读复查；发现冲突就停，不暂停旧系统或清掉旧unknown。**新gate目录只协调新系统，不是跨新旧系统的原子共享**，不能将本次单账号试点宣称为长期并行生产验收。

冻结范围还包含sender身份hash、商品卡业务绑定、模板正文/版本及稳定收件身份。批准前不打开真实运行环境；执行前及提交时再次核对暂停、有效期、源版本、租约和scope。模块只有模板与卡片执行，不自动样品审批、选入商品或创建新链接。
