## 实现与边界

- IT、BR、MY、UK 正式持续发送共用 `delivery_reconciliation.py`：只核验原账号、原请求、原 CID/证据，没有重建会话或重发组件的入口。新非 IT 投递冻结发送账号及 IM 身份；旧三市场意图按原实现固定账号兼容，配置换号拒绝读取；IT 校验原 senderBindingHash。
- 建会话最多两轮，每轮 180 秒、最多 101 页；卡片与文字各最多三轮，每轮 90 秒；相邻专项轮至少间隔 300 秒，从首轮起总期限 900 秒。首次正常提交后的即时回读不计专项轮次。次数在远程读取前记入既有 `cycle_delivery_check`，进程中断、跨日或新窗口不清零。
- 卡片保留两次成功历史缺失、间隔至少 300 秒即可提前隔离的合同。认证失败、超时或历史不可读只记读取未完成，不伪造不存在。建会话列表有返回上限且无原请求关联；即使有同达人 CID，也不猜 CID 继续发卡文。
- 耗尽后投递为 `quarantined_unknown`，原会话意图、unknown/confirmed/未提交组件及冻结快照保留。只阻断同市场/OEC 的主动营销，换账号、PID、计划或跨过 72 小时都不放行；不改关系为 human、不新建技术人工案件，原案件与拒联保留。
- 精确迟到回执可幂等结算原组件，但不重新打开隔离投递。专项回查确认卡片时，同事务关闭从未提交的文字，避免进程恰在确认后退出、下一轮误补发。已持有原建会话回执的恢复可核实原 CID 并关闭未提交卡文，不能用列表匹配替代回执。
- 发送池将技术隔离归入暂不参与，独立说明原因；状态接口不把隔离组件保留的 unknown 误算成全市场仍待核验。共享派发槽释放后，其他达人正常按原门禁推进。
- 每市场执行锁覆盖整个发送/核验函数及收口；旧执行器未退出时不能并行释放阻断。原逐写账号锁、授权、窗口、额度、暂停和关系门禁保留。调度器可按既有持久授权拉起因 unknown 退出的 worker，先进入有限只读核验。
- 建会话业务码 201 仍保持原明确商业拒绝/案件分类，平台额度拒收仍走原额度暂停。本批不更改卡确认后遇新入站时允许发完原邀请的规则，该改动仍按 §9.13 单独实施。
