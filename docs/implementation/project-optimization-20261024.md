# 自主运行、发送可靠性与页面精简

2026-10-24，开发基线 `0d53b3d`。用户确认沿用现有业务规则和持久授权：已允许的工作自动处理，无法判断和超出规则的事项交给人。本文记录本批变更和验收；当前规则见 [PROJECT](../PROJECT.md)，实现合同见 [TECHNICAL](../TECHNICAL.md)。

## 修复范围

| 问题与证据 | 改动 | 保留的边界 |
| --- | --- | --- |
| FR/TH 前夜原投递未知，发送窗口关闭后不再主动核验 | worker 与 scheduler 区分原提交核验和新发送；停止、暂停计划与窗口外仍可有限只读核验 | 原账号、意图、requestRef 和核验预算不变；未提交组件不推进，未知不重发 |
| 短暂读取网络错误让 sender 反复退出 | 四次有界退避，耗尽回到原异常状态；已提交未知必须有台账才进入核验 | 只处理明确的读取网络错误；其他错误仍暴露 |
| 页面与调度并发启动时可能重复 spawn 或覆盖 PID | 发送器与 scheduler 复用启动锁及原子 JSON 发布；watch 在锁内保留停止标记 | 显式启动才解除 scheduler 停止；停用且无原提交不启动 |
| 子进程 PID 晚于旧心跳，父进程退出后可能误释放其资源槽 | PID 与观测心跳在同一事务交接，校验 owner/fence | 旧执行者不能续租、交接或结算；仍活跃子进程保留原槽 |
| BR 身份库约 58.6 万条；概览读取约 32 秒，超过 Web 30 秒期限 | B 作者按输入小集合复用现有别名索引定位，再核对当前身份；总览与发送池共用只读查询 | 历史别名不能路由；跨市场、冲突及歧义身份排除；缺失与错误不补零 |
| 一个慢分区消耗后续概览分区的查询预算 | 各分区重新计算读取期限 | 某项读取失败不连带取消其他分区，不延长平台写入预算 |

身份列表增加按市场、最近观测时间的增量索引，由正常 `CreatorIdentityStore` 打开时幂等创建。概览优化直接使用已有索引，无需先迁移真实库。

## 页面与文档

- 一发与样品：待处理申请前置，未知优先；履约等待和历史默认折叠；商品长名称收起，完整内容仍可查看；只展示当前适用动作。

- 首页、二发与概览：先显示人工事项、等待、结果与当前操作；日常设置、速度、统计口径和历史证据按需展开。未知、当前异常、失败及旧数据提示保持可见。
- README 提供当前入口与全链路概述；TECHNICAL 增加关键文件导航和恢复合同；PROJECT 写明本次确认的自主范围，纠正已统一的登录恢复状态；文档导航合并重复入口。

原生产 `config/jobs.json` 和 `docs/handoff/current.md` 的未提交内容不纳入本批提交。

## 验证与限制

独立 worktree 验证：Python 全量 2,080 项、Web 全量 225 项、build、随后 typecheck、文档链接与 diff 检查通过。后续暂停计划和恢复检查的最终修订另通过对应发送与调度合同。测试覆盖并发启动、停止竞争、stale fence、原未知恢复、暂停/窗口边界、未提交不推进、市场隔离及歧义身份拒绝。

只读真实数据检查中，BR 概览由约 32 秒降至约 11 秒，六分区均可读；原先可读的库存、身份、发送池指标一致。七市场原提交检查复用现有活跃投递索引，由约 2,075 ms 降至 2.59 ms。这些是当次本机测量，不是吞吐承诺。

六步真实页面审计覆盖运营首页、二发、一发、样品明细、经营总览和会话；截图及笔记保存在本机 `outputs/frontend-audit-20261024/`。回归与只读检查证据位于 `outputs/optimization-20261024/`。
