# B.14 按待发需求补齐商品素材与Campaign卡

2026-09-13。本次用户误暂停的是开发回合，后台批量、身份、供给和收信仍运行；先核对PID/状态再更新进程，未重复投递。接续目标仍为本批500与平台日限额信号实测。

## 修复的供给堵点

发送候选过去仅扫描前5个PID，素材任务也固定取同一组商品；新线索虽然入池却无法发送。现在发送选择检查全部当前候选PID（有界1000），素材按未触达、未冷却且控制允许的达人需求排序，每次最多准备5个商品名称；已具备名称和当前核验卡的商品跳过，无需求的商品不新建材料。

advance-cycle-materials.py串联名称缓存、卡片查询、准备意图、单项创建/回查。每轮至多1个新卡创建；有started/response_saved/unknown时只核验既有意图，不重新创建。材料子进程返回0但业务status=unresolved仍判未完成。父子进程中止时终止自己启动的子进程组，业务结果留在持久意图中核验。

材料周期改为60秒。生成/读取只是准备新的商品，不改变已冻结的旧发送材料，因此不会因当前正在发送而把补料节点一并停住；货盘版本刷新仍在有冻结任务时延后。材料步骤最多等账号读取锁30秒，避免反复把临时占用报成失败。

## 自动回复纠错

此前真实入站“certo”被模型误判为unclassified，已自动发出一次人工确认句。它是已送达的真实错误，保留原分类、发送回执和service_correction记录，不把它作为正确问答验收。严格核对消息/控制版本后关闭误建事项，没有追加补救消息。

简单肯定、复合致谢和常用积极表情先用规则识别，不追加消息；带新问题的复合句仍保留问题。模型分类版本升为v2，加入最多1000字的最近已确认外发文字作为上下文，不给内部佣金、原始身份或完整历史库；证据引用仍只能来自入站原文。历史分类不会自动变成新回复。
