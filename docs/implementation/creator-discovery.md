# 批量 handle 发现与入池

2026-09-12。本步骤接续稳定身份和 OEC 刷新，提供从新名单扩大达人池的入口；仍只读取意大利平台信息，不发送消息。

## 使用流程

在达人库点击“批量添加达人”，填写来源名称并粘贴 handle、@handle 或 TikTok 达人主页链接。每行一个，或用逗号分隔。纯本机“检查名单”显示有效、重复、无效项及原因，不访问平台，也不创建抓取批次。输入或来源变化后需重新检查，不能提交旧预览。

“开始解析并入库”只安排有效且不重复的输入。单批最多 500 项、文本 64 KiB，是单请求技术范围，不是每日触达或采集上限。格式错误不会静默消失；长纯数字若未明确加 @，提示可能是 ID，不自动当作 OEC 或丢弃。

结果区区分新增达人、已有达人、仅取得 OEC、未精确匹配、未完成、重复和无效。可直接打开成功取得身份的档案。待解析列表的“重新解析”只预填该条，不自动重跑全部待解析名单。

## 身份和来源

- 新输入按当前 handle 精确 Find，不能因历史同名缓存就跳过身份核验。当前返回相同市场/OEC 时归入原 creatorId，不新增重复达人。
- 已存在档案的“刷新画像”继续固定按 OEC 运行；新名单入口不替代这条路线。
- 如果 Find 已核验 OEC，但后续 Profile 失败，保留稳定身份及当前 Find 证据，标为仅取得 OEC、画像未完成；后续可在档案按 OEC 补全。
- 找不到精确 handle 时保留线索，不回退相似结果。已有同市场/handle 的未解析线索被复用，重查不增加同名待解析副本。
- 成功解析可以给既有 pending 线索补上本次当前发现身份，但历史第三方记录归属仍未证明。既往 resolved 线索不能因名字被另一 OEC 复用而改绑。
- 首次新增/已有的分类与来源标记在身份库同一事务提交；重新结算已有报告不会把“新增”改成“已有”。

## 持久任务与暂停

批次和逐项状态保存在新项目 `var/creator-discovery.sqlite`，与 OEC 刷新队列、身份库、匹配库和二发业务库分开。同一个提交/控制请求编号幂等，不同内容复用编号报冲突；未确认请求在页面保留原编号。

Worker 每轮顺序处理 OEC 刷新和 handle 发现，复用同账号现成 HTTP、验证/重放和请求节拍器。每项独立冻结输入、租约和不可覆盖的输出目录；失去租约的旧 Worker 不得导入结果。重启后有最终报告先幂等结算，没有最终报告则保留未完成状态，不盲目重跑。

暂停只停止领取后续项目，已发出的只读请求可以收尾保存。账号、验证或平台错误会阻断后续领取，余项保持未开始；“继续未处理项”只处理 queued 项，不自动重跑已失败项。已取得 OEC 的不完整项目仍可从档案 OEC 刷新入口继续。

## 运行边界

页面入口在 `/creators`，服务为 `/api/creator-discovery`，只接受本机 Host/Origin 和白名单字段。请求只能包含名单、来源、市场、预览哈希及请求编号，不能指定账号、Cookie、OEC、脚本或路径。

在 `apps/web` 运行 `npm run identity:worker` 即可由同一个采集 Worker 处理两类任务。独立 CLI `scripts/creator-discovery.py` 还提供 preview、submit、list、detail、control；preview 不打开数据库。常驻采集只启动一个协调入口，不另外并行启动同账号发现 Worker。

本轮不安装开机自启、不修改旧 BDHub 代码/业务库/凭证，也不把新资料自动覆盖历史匹配结果、冻结稿或未知发送状态。MX/BR 的批量发现尚未在此页面开放。

## 实测与验收

使用意大利已有资料构成 5 项输入：1 个尚未入新身份库的达人主页 URL、1 个已入库 handle、1 个已有待解析 handle、1 个大小写/@重复项、1 个非法项。只读预览返回 3 有效、1 重复、1 无效；Node→Python 预览前后没有创建发现数据库、没有平台请求。

通过页面提交后先暂停，启动新的共享采集 Worker，实际保持 3 项 queued、开始数 0；明确继续后才抓取。关闭弹窗并重载页面仍能打开原批次查看进度，最终结果如下：

| 项目 | 实测 |
| --- | ---: |
| 新增达人 | 1 |
| 归入已有档案 | 1 |
| 未精确匹配 | 1 |
| 重复 / 无效 | 1 / 1，均未请求平台 |
| Find / Profile 调用 | 3 / 4 |
| 总业务请求 | 7 |
| 本轮平台验证挑战 | 0；仍沿用完整验证/重放实现 |
| 正式身份数 | 31 → 32 |
| 待解析线索 | 17 → 17 |
| 来源线索 / 身份观察 | 50 / 74 |
| 旧库写入 / 真实发送 | 0 / 0 |

同一个提交请求回放返回原完成批次，批次数仍 1；修改名单却携带旧预览哈希返回 409。所有现场身份文件校验不变，临时签名/验证材料均已清理。两份匹配库与二发业务表内容 SHA-256 前后一致，旧服务健康回读 ok。

185 项 Node 测试、125 项 Python 测试、TypeScript 和生产构建通过。测试涵盖原子新增归属、崩溃后同报告幂等结算、Find 成功但 Profile 失败的身份保留、身份冲突拒绝、暂停期间失败仍保持暂停、旧租约拒绝写入、未匹配线索复用、预览失效和输入边界。现场没有刻意制造身份冲突或 Profile 故障，这些由隔离测试验证。

浏览器已检查预览逐行显示、修改后提交入口失效、暂停与继续、重载后找回批次、结果跳转档案、单条待解析重查仅预填不自动提交，以及 390px 弹窗无横向溢出。修正了结果链接未关闭弹窗、旧刷新面板网络错误未清除和共享关闭图标未填色的问题。
