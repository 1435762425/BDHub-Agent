# 二发闭环 B.1：本地控制与供给队列底座

2026-09-13。实现蓝图B阶段的第一部分，未宣布整个B阶段或完整自动循环完成。旧BDHub只读，本轮平台请求/发送/模型调用均0。

## 已实现

- `scripts/lib/second_cycle.py`：机构×市场唯一计划，稳定creator/OEC关系控制、事件幂等与版本校验；拒绝/人工控制不因重复来源导入被解除。收到新消息延迟60秒，延迟结束不自动视作服务已处理。
- 商品资格：精确数值，库存>100、剩余期限>45天、达人佣金>公开佣金、明确可用；评分>4仅偏好；缺失、非法、明确不合格分开。只有PID和offerKey都匹配才计入条件齐全候选。
- 完整货盘版本与部分版本分开，旧版本/半成品不能覆盖最新完整版本；同一时点矛盾快照拒绝。
- 容量输入分新联系和已解锁池；新联系参数最多500，与登录账号数量无关。先扣可用的唯一达人和待采估计，再有界选PID；输入是本地规划参数，不声称已查到平台剩余额度或重置窗口。
- 每个PID作业固定14天窗口，保存游标、页面、租约和fence；源变化/暂停阻止迟到结果提交。容量缩小停止新领取。页面提交、来源边和机会同事务，重复来源不增人；不同统计窗口采用最新观察，不选历史最高销量拼接。
- `scripts/second-cycle.py import-italy`：只读现有意大利来源和身份解析链，写新`var/second-cycle.sqlite`；明确当前身份与历史同品归属的区别。新项目原机会库中的明确暂停会首次带入该底座；不是实时双向控制同步。
- `/api/second-cycle`只有GET，只读打开SQLite，不提供任意计划、数据库路径或发送参数。
- 现二发工作台新增“二发供给 · 本地准备”，显示关系、来源边、机会及每款条件缺口。正常读取不写库，浏览器刷新后可再次读取。

## 当前意大利导入结果

5个历史商品、50条来源边、31个稳定关系、33个有当前身份的达人×商品机会；17条未解析来源边保留，未创建虚构关系。原来源48人是来源达人计数，与33个关系商品机会不能混比。

Freegrin读取已有单卡成员观测，保留其库存与达人/公开佣金，但该输入没有活动有效期和完整可用状态，所以仍待补。其余4款还缺库存/佣金等条件。条件齐全达人0，不捏造新鲜事实或用测试数据解锁真实候选。原始身份库、旧试点和历史草稿没有改绑。
