# B.9 意大利入站事件底座

2026-09-13。只读平台轮询；本地事件入库与关系投影，无模型调用、自动回复或真实发送。

## 已接通

`scripts/poll-cycle-inbox.py` 将已索引且已关联二发关系的IT/ACC6会话，按最久未核验顺序轮询：608核实OEC/CID，301取最近20条元数据。运行默认单轮；`--worker --limit 12 --interval 60` 持续轮询，每轮55秒截止，失败至少退避300秒。独占本地锁防止双Worker。暂停文件 `var/cycle-inbox.pause` 或计划暂停会停止后续远端读取；SIGTERM退出，不改旧服务。

平台事件按计划（机构×市场）、CID、server message ID去重，记录OEC、消息类型、field10时间、观察时间与历史标记。原始正文、ticket、Cookie不入库。相同ID身份/分类冲突整页回滚，不覆写；记录与关系/待处理水位在同一个SQLite事务中提交，重启后重复读取不重复处理。

首次读取建立baseline，全部作为历史。之后早于baseline、时间缺失/异常或存在缺口的事件不作为新回复。后续真实新回复才进入 `inbox_pending` 的 awaiting_content 状态，最后一次新事件之后60秒到期；重复事件不延长。消息内容尚未拉入处理管线，因此本状态不会自动触发LLM或回复发送。

历史或新收到的已识别回复/加橱窗证据可更新 unlocked，人工模式和拒联字段保持；加橱窗不安排催拍。此处解锁只表明互动证据，不取代当前平台额度、频次及拒联检查。缺少足够连续记录且hasMore=true时标记gap并阻断营销，禁止自动回复；缺口补回尚未实现，不静默跳过。

11个已关联会话，首轮46事件：我方42、达人回复1、已识别加橱窗通知1、其他2。全部历史补录，回复待办0、缺口0、真实发送0。第二轮读取同11会话，新增0，验证去重。未将其他通知猜成回复，不推断加橱窗PID，不使用样品记录解锁。

运行文件：`var/cycle-inbox-status.json`、`var/cycle-inbox-worker.pid`、`var/cycle-inbox-worker.log`。持久表位于新项目 `var/second-cycle.sqlite`：inbox_checkpoint、inbox_event、inbox_pending。页面二发供给面板展示事件数、历史数、待取内容、缺口和最近核验时间，每15秒更新；时间不等同进程健康证明。

## 覆盖边界与后续

这是对现有索引中已关联的11个会话轮询，不是整个意大利IM全量监听，也未自动发现后来新建的会话。当前301每页20条，首次历史仍可能不完整；不把完整返回页等同全历史。后续接初始化索引增量刷新、缺口回补、原文/附件取回和问题分类。新回复只到awaiting_content，人工接续/回复Agent/发送仍未接通。

月度消息刷新规则继续独立核验，unlocked不因历史5条清除，也不自行把时间过一个月当作平台回执。

验证：入站8、IM解析11、second_cycle31，共50项通过；前端生产构建和运行API另行回读。未制造达人回复进行测试，历史读到互动不等于在线新消息的端到端验收。
