每PID从GMV前50中最多取10位有出单者，合计48人中46人仅出现一次、2人各出现两次；44条短视频销售边、6条直播销售边。销售渠道不是视频发布时间，也不证明现在仍持有商品。`matched=null`不是无同品关系：本次没有传reference_pids，精确关系来自PID查询和返回字段。

Kalodata ID与OEC使用不同身份命名空间。48人均保存外部身份，`oecId=null`；关系控制为`unknown`，拒联状态为`null`。没有复制联系人、头像URL、浏览器身份、凭证或IM历史。

额外只读调查发现7月30日的旧画像快照有3,978位意大利达人，其中20人与本次样本handle相同。但画像已标过期、价格带为空，而且交集内Kalodata ID与OEC均不同。本次不将这些历史handle交集自动认作已核验的当前身份。后续可单独建立带日期的身份映射证据并评估画像可用性。

源窗口只有日历日期、未提供时区。存储用UTC编码原日期，同时在`FactSource.windowBasis=calendar_date_unknown_timezone`标明其语义；界面显示原日期而非转成北京时间跨日。该标记随达人来源和精确销量观察进入评审包，不能解释为已核验的UTC起止时刻。

## 一发为什么仍需补资料

本次48人没有可确认的类目、价格带和完整内容画像，5商品也没有已核验分类。53次一发双向探查共返回480次候选展示，均走缺资料探索路径；其中同品信息只是已有证据补充。这里不把探索列表称为有效一发推荐。

下一步先验证旧画像和商品分类的适用性，确定哪些字段可以作为带日期的特征，哪些需要增量补齐；再用人工认可的配对与反例评价一发。模型只处理难以结构判断的少量资料和单关系小包，不能用当前5×48小样本推算真实运营质量。DeepSeek-V4.1-Flash的实际token与思考输出仍需后续真实调用计量，本轮没有花费。

## 复现与实现

在`apps/web`执行`npm run import:italy`。脚本固定读取上述范围、验证市场/查询模式/窗口/身份精度，将允许字段写入新项目`var/matching-italy.sqlite`。任何拒绝行都会阻止本轮导入；源指纹变化不会覆盖已有数据集。重复运行保持事实幂等，评估另建临时库并在完成后清理。

- 原始字段适配：`src/server/matching/italy-import.ts`。
- 双向集合与上下文验证：`src/server/matching/italy-evaluation.ts`。
- 最小本地事实与含历史商业观察的报告：`var/italy-offline-batch.json`、`var/italy-offline-import-report.json`，不进入Git。
- API只允许`dataset=demo|italy`，不能传入任意文件路径。缺少意大利库时提示先导入，不以合成数据补位。
- SQLite身份schema v1→v2允许OEC未知并独立保存外部ID；原合成事实、子表引用、历史记录保留，旧缓存按版本失效。
- 真实数据禁止演示调价/库存修改。已知拒联、人工接管或暂停仍阻止评审；未知控制只可准备`executionBlocked=true`的离线资料，不赋予执行权。

工程检查：92项测试通过，新增覆盖真实字段适配、金额与币种、命名空间、未知值、源窗口、版本迁移、数据集隔离及双向回放；类型与生产构建验收见最新运行记录。浏览器点验记录见[design-qa](../../design-qa.md)。
