本轮用户要求：主动推品冷却统一 72 小时；机构后台消息进入会话和 AI 上下文；肯定合作且未观察到当前商品橱窗证据时，按市场语言提示添加卡片。合同已收敛到 [PROJECT](../PROJECT.md) 与 [TECHNICAL](../TECHNICAL.md)。本轮已发布 Web 和相关 worker：MY 6 个会话的 7 条机构正文经本地台账与 HTTP 时间线核对，缺口/重复均为 0；只证明本次已观察窗口，不代表全量历史。四市场指南 revision=1，7 个合成模型案例（四市场肯定、MY 已加/感谢/已提醒）符合预期；这不是生产准确率。API 冷却均为 259200 秒，加载期间原持久授权不变，新发组件数增量 0。运行回执保存在本机 outputs/audit-remediation-20260923，最新数量见交接。

## 结构优化边界

- `operations_scheduler.py` 同时处理到期、阶段执行、报告解码和 worker 监督。按这四个职责逐步拆模块，保留 `operations_workflow.py` 为唯一持久状态机，避免再造调度台账。
- `reply_events.py` 同时承担事件投影和历史评测。拆出历史 V1 评测读侧，当前消息事件由会话与 V2 共同消费；增量游标按市场/会话管理。人工与 Agent 的 transport 已可共用，业务决定继续独立。
- IT 与其他市场发送路径有重复复检/回执逻辑。共享不可变意图、资格、组件结算和 reconcile 合同，各市场保留 transport/能力适配；不要用一个大函数吸收所有市场分支。
- 商品来源保留全托/Campaign 独立资格，统一 current binding 和阶段报告；A/B 保留不同采集证据，统一位置与稳定身份。目录移动与业务修复分开，避免文件改名掩盖合同变更。
- vendor 静态无引用不是删除证明。先列当前入口的动态导入/资源闭包和本地补丁，再分组删候选，每组跑离线导入及实际入口合同；协议 manifest、许可证和原意图证据不按文件大小裁剪。
- 文档只保留一个当前合同归属。已删除纯跳转及过时执行提示；保留有真实请求/响应、事故或人工标注价值的历史报告，不为每次主文档压缩新建整份归档。

## 历史实测与推论限制

1. [四市场正式启动报告](four-market-launch-implementation-20260923.md)：2026-09-23 容量未满时 IT 约 5–7、BR/MY 约 7–9、UK 约 4–6 位/分钟；BR 有界并发约 8–12，UK 8 人 56.6 秒/4 人 29.4 秒。每市场 30 未达到；容量满后速度 0 不可用于吞吐结论。同期 IT 老水位滞后、未知建会话隔离及非 IT showcase plan 错用，是提升可观测性与市场合同测试的直接依据。
2. [OECID 吞吐](identity-oecid-throughput-20260920.md)：728 待补中 498 可本地复用历史终态，真正需要查询 230；82 位真实只读 cohort 用时 160.8 秒（约 30.6 位/分钟），无验证码。身份查询吞吐不能外推 IM 发送；“少做重复请求”已有直接收益证据。
3. [V1 人工评测](reply-model-evaluation-20260920.md)：35 条 IT turn，DeepSeek 28/35，2 条误自动处理；双模型一致仍有误判。该政策是旧五动作且无 link_usage 真值，不能代表 V2、多轮或 BR/MY/UK 准确率；可复用人工标注方法，不沿用历史开关决定。
4. [零销量视频证据](kalodata-zero-sale-video-evidence-20260920.md)：五 PID 样本提供 B 类线索可行性，不能由小样本推断全池获客或成交提升。应按实际 A/B cohort 跟踪后续结果。
5. [当前交接](../handoff/current.md)是带时间快照，记录的 IT needs_human、测试通过或进程存活均不证明当前已恢复。实际核验使用 mode=ro 台账及原平台只读证据，不能把本文建议当完成记录。

## 2026-09-24 接续结果

- 历史补扫已实现原生分页、持久断点、身份校验和与热读隔离；MY 一会话跨进程读完 3 页 13 条，缺失/重复 0，pending、授权及发送台账不变。此样本原本已落库，证明分页和幂等，不证明全市场历史已回补；批量调度及延后热读项恢复仍需建设。
- V2 新增四市场 × 12 多轮案例。生效旧指南第一轮筛查 37/48；修正规范与指南后，最终新一轮筛查 47/48。保留 MY 无卡场景主动澄清且 route/waitFor 冲突的失败，原校验拒绝；另有三条内部中文解释精度观察。合成样本非真实业务准确率，后续应积累真实匿名化多轮标注。
- IT 核验定位为原活动与当前子活动映射证据不足，两 PID 即使在已选池，也不能证明原请求成功。保留原请求、回执及停滞状态，隔离后继续还是先补映射证据由用户选择；没有恢复主链。
- 备份保留建议、恢复演练与只读发送诊断已实现。31 份完整备份 hash/quick_check 通过；最新 33 库约 1.48 GB 在空临时目录恢复耗时 5.043 秒，验证后临时副本清理。当前保留策略删除候选 0；异机副本尚未完成。
- 近 24 小时样本完整确认触达 IT 497、其他市场各 500；首末触达区间均速 IT/BR/MY/UK 为 2.972/3.924/3.716/2.735 人/分钟。该区间包含等待，不能当有效发送时段容量；4,999 个确认组件均关联确认回查，但认证分段样本缺失，尚不能指认吞吐瓶颈。后续应先补分段计时，再决定是否减少认证开销或扩并发。
