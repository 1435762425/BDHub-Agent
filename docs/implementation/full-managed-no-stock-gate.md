# 全托取消库存数量门槛

2026-09-14，用户明确：“全托商品不保留这个硬门槛，不需要库存数”。覆盖之前全托库存>100及因缺少库存而阻塞的规则。

## 当前行为

- 全托商品不要求库存字段，不解析库存数作为商业准入依据；None、0、1、100及无法解析的数量都不能单独造成不合格。
- 当前Offer与卡片准备投影将全托stock标为None/stockRequired=false；源页面不显示库存数字。历史快照与接口原始证据不删除。
- 全托身份来自官方高机会“仅全球销售”PID证据，或当前原生全托活动类型8/9。不能把所有selected路线或无证据标签都视为全托。
- 普通/未证实为全托商品仍要求库存>100。
- 活动期限、佣金优势、商品/列表绑定、下架/治理/失效门禁保留。已知unavailable_type=8是暂时缺货，全托不以其作为库存变相门槛；其他不可用状态不放开。旧快照available=false且原因不明时不擅自推定为缺货而恢复，需新平台状态核验。
- 不为库存单独查接口，也不为拿库存先把大量候选选入。为实际选入状态、当前活动和商品卡绑定而必要的查询保留，顺带返回的数量不参与全托判断。

## 实施

- product_stock_policy：集中定义全托证据、数量要求和暂时缺货状态。
- cycle_catalog：新平台响应保留全托类型依据，全托标准化不要求数量。
- cycle_product_management：把完整、身份一致的官方全托源证据投影到新Cycle库。当前10000 PID已同步，对应当前货盘2819个Offer不再要求库存。
- CycleStore._offers：当前策略投影，不改不可变货盘；历史只因库存被挡的全托Offer解除该策略hold，保留原invalidated记录。其他hold不解除。
- CardCreation：只允许纯库存策略变化造成的未提交prepared意图被新准备版本取代；started/unknown/response_saved不替换。
- inspect_card与fresh_card：全托不再因数量缺失或低库存失败；旧已发送快照在本次只读核验中应用当前产品策略，不改原快照或重发。
- global_source页面：移除库存数字和“待库存核验”，改为活动/佣金/选入方案核验。

## 证据与验证

库存成本只读实测先于最终业务决定：1款1次请求约1.59秒、10款1次约1.77秒、100款1次约6.30秒，均返回对应库存，另有6.19秒初始化/等待。证据var/stock-read-benchmark-20260914.json。该结果不作为保留门槛的理由，按用户明确业务决定取消。

实际投影验证：当前2819个已证实全托Offer，要求库存数的数量为0；3393个普通/未知Offer保留原规则。之前仅因库存不足被挡的PID 1729480033890900437 当前评估不再出现库存阻塞，历史意图仍保留invalidated。没有为验证发消息或新建TapLink。

回归覆盖：缺数量/0/低数/非法数、普通商品不放宽、佣金/期限/下架仍挡、暂时缺货、源机构身份隔离、只解除库存hold、未提交策略变更、未知不可替换。AI自动回复保持enabled=0，旧试点和额度暂停不恢复。

已完成5项专项库存策略测试、151项Cycle回归（含来源性质投影）及前端构建验证。历史旧试点的冻结规则不改写，也不恢复其执行；当前二发、商品卡准备与回复事实读取统一使用新全托策略。
